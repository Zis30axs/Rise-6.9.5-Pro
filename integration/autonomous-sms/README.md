# 剧情外主动短信

基线：`lite@800ac0138198a904189f25b27c3e8b11a09daaf9`（已合并 PR #50）。本次沿用已有机制，补上手动回复隔离、正文去重、过期任务与失败保存的边界。

## 运行方式

- 已核对本卡 `bridge.ts`、`story-api.ts` 及既有 `AGENT-ADAPTER-RESEARCH.md`。普通角色卡没有已确认可调用的通用 subagent 接口；Tauri Agent 属于特定宿主能力，本功能不依赖它，不引入额外服务或开发助手的子代理。
- `autonomous_sms` 是独立的一次模型任务，沿用「状态 → 独立叙事引擎」当前选择：自定义接口走原来的 Chat Completions / Responses 请求；酒馆模式走 Tavern-Helper，`max_chat_history: 0`。不新增原生聊天楼层，不切换用户模型，也不在失败后偷偷换用另一条 API。
- 世界状态成功保存并推进游戏分钟后，最多每90个游戏分钟检查一次；通过25%随机抽签后只选一位当前主角已有的联系人。每位收件主角每天最多两条，同一发件人对同一主角冷却360分钟；07:00前及22:30起不安排。大跨度时间推进不补发错过的窗口。
- 窗口、候选和已发送记录随存档保存。界面每1.2秒只查看有没有已保存候选，并不按现实时间抽签。模型仅在空闲、前台、当前聊天内运行；玩家无需确认。
- 子任务只得到发件人自身的日程/待完成活动、已保存经历和双方会话。NPC 使用自己的设定与当前作息；其他主角使用本人存档。收件人的私人日记、其他会话及全局周报不进入这个任务。模型可以返回 `text: null`；无合理动机时不生成消息。

## 安全边界

- 待玩家点击「让对方回复」的私人会话不会成为主动来信候选。生成期间若玩家新发了问题，提交时再次检查并静默放弃，原消息继续等待手动回复。
- 乐队邀请继续通过原有邀请消息和结构化同意登记。主动短信不能增删成员、接受邀请、改变日程、转账或执行任何世界行动。
- 不同候选ID也会检查同一会话最近20条来信和收件箱：忽略空白及全半角差异的重复正文不再发送。任务ID仍保持幂等；其他联系人的相同文字不影响本会话。
- 候选只在它对应的游戏分钟有效。玩家推进时间或切换主角后放弃旧候选；重载出来的旧任务也不会读取未来上下文并倒签发送时间。纯现实等待不会使它过期。
- 收件箱、权威会话及通知一起构造，保存成功后才发布到界面。容量不足时静默放弃，不能先裁剪收件箱再发现通知无法写入。未读消息不为腾空间被删除。
- 模型失败不写正文。若连“放弃候选”的状态也无法保存，同一已挂载界面仍只尝试该候选一次，避免每1.2秒重复请求；重载后继续受已保存候选和游戏时间校验约束。前景剧情可以抢占后台任务，后台结束不会清除前景的忙碌状态。
