# Lite · 七游戏日记忆与正则变量裁剪

本变更专门处理双主角 PR #10 之后的长线叙事连续性与每轮模型提示词重复上传。基于 Lite 的源码分支，尚不代表新 PNG / 离线 ZIP 已发布。

## 两种不同的数据

1. **权威存档**：完整的 unread_city 聊天变量。余额、背包、手机、日历、日记、最近 40 条正文、动作收据、后台游标及各自进度照常校验并保存。不会对存档使用正则删字段。
2. **发送给模型的短上下文**：从本人的权威状态每轮重新投影，写入一次 user_input；仍然使用 max_chat_history: 0，因此不能只发送「变更增量」。不直接发送完整双主角存档，也不接管酒馆其他脚本。

## 7d 全知记忆：一份全局总结，不分主角

- **按游戏时钟每 7 天形成一个世界周期**，素世、祥子的所有合法事件和共同经历进入一条带人物来源标签的时间线。
- **由现有剧情 LLM 以全知视角撰写一篇世界总摘要**，可以同时知道两名主角的秘密、动机、分离时的日常及互相尚不知道的事情。摘要不是任何角色本人的日记。
- 在第 8、15、22 天等跨周边界，运行时只登记一份待总结证据包。下一次正常故事生成时在同一请求中让 LLM 额外返回 weekly_summary JSON 标签（week 和 text），**不另发后台模型请求**。
- 前端仍正常取得 story、phone_messages、world_actions。weekly_summary 属于额外、严格校验的摘要输出；与当轮剧情一并事务保存。生成失败、切换聊天、错误周次、不合法标签时不写入。
- 每周的候选证据全局最多 56 条，每游戏日最多 8 条；结周择取最多 28 条；LLM 写成最多 1800 字摘要后删除待总结证据正文，但保留来源 ID 以便追溯。保存最近 12 周；正常提示中引用最近两份完成的全局总结。
- **全知叙事 ≠ 角色全知**。LLM 可以知道两条私生活，写当前视角的剧情仍须区分「真正知道」「玩家知道」「仅叙事模型知道」的不同层次，不得自动让角色读心、获知另一人的隐私。
- 旧 1.12 存档在当前世界时钟初始化空的全局归档；不补写过去不存在的摘要。
- 权威的余额、订单、路程、状态、消息回执仍然仅由运行时控制；全知周报不会给角色新的可执行行动。

本功能的模型总结使用**正常发生的下一次剧情调用**；若周界已越过但玩家还未继续叙事，归档状态先保持 pending 而不是声称已经生成总结。不同周有多个 pending 时按时间顺序逐轮处理，不能跳过任一周的证据。

## 正则裁剪与提示词缩减

src/runtime/prompt-pruning.ts 只从**历史模型上下文投影**清理明确包裹的机器变量片段：

- <unread_city_state>...</unread_city_state> / <unread_city_variables>...</unread_city_variables>
- 带 unread_city_state 或 unread_city_variables 语言标签的代码块。

不会全局删除 JSON、普通中文对白、酒馆原生变量、用户本轮输入、姓名-情绪-对白的竖线标记或 story 标签。解析保留原白名单和原子结算；只是避免已存在的变量回显再次成为 LLM 的文本历史。

此外 bridge.ts 中将全局行动目录由完整描述/效果/各地点营业状态改成轻量的 ID 索引。当前位置实际可执行服务报价、场景及权威 player 仍保留；学业详细课程、所有房间交互等只在相关主题出现时展开。保存的个人故事从最近 8 条 × 1000 字缩为最多 6 条 × 650 字，近期手机从 20 条 × 1000 字缩为 8 条 × 280 字；日记限 7 条 × 300 字并按来源 ID 避免和本人后台经历重复。日历只发送未来两周以内的近期安排；主角已确认的主要人物介绍限 16 人 × 350 字。

注意：模型仍能正常选择有 ID 的行动，真实数值、收费、出行、消息和物品变化由运行时校验。不能将短上下文误说成「停止写入聊天变量」；保存到 Tavern-Helper 的 unread_city 快照仍然完整。
