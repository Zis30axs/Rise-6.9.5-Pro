# Lite · 全知叙事七日记忆与提示词裁剪

## 总原则
- **仅有一份世界级七日总结**，不是素世、祥子分别总结。
- 同一个叙事 LLM 可以同时看到两位主角的已保存事实和各自未公开的事件，以全知叙事者视角综合情节。
- **全知叙事不代表角色全知**：某位主角未见过、未被告知的秘密不得被写成角色自己的记忆、知情和行为依据。
- 七日以游戏时钟计算（第 1–7 天、第 8–14 天），不是现实日历。

## 存档与生成
- 对两位主角的事件与故事登记来源 ID，统一归档在 weeklyMemory 世界级对象；周次闭合后暂存两人证据。
- **下一次正常叙事请求复用同一次 LLM 调用**，把待总结证据交给模型，要求在独立 weekly_summary 标签内写 1800 字以内的全局剧情摘要。没有周次则不生成。
- 生成结果经过周次、长度和字段白名单检查，并在前台故事事务提交成功时一并写入；取消、不合法输出或存档失败时保留待总结证据，不能只保存摘要。
- 摘要写入后删除该周重复长证据文本，保留来源 ID；提示词只需要最近两份已完成周报。完整世界状态的余额、交易收据、背包与实际地点不被总结替代。
- 旧存档在当前游戏时刻初始化，不追溯编造已经过去的整周。
- 如果一个游戏动作跨越多周，没有证据的周不编造摘要。

## 正则裁剪
- 只从已经保存的文本在**提示词投影**里去掉明确标识的 unread_city_state、unread_city_variables 包裹的机器状态回显，以及同名标签的代码围栏。保留自然语言、普通 JSON、对话格式及原文存档。
- 压缩服务、商品、课程和室内交互的发给 LLM 的目录表示。保留当前场景权威状态和本轮玩家输入。
- Tavern 的 max_chat_history=0 保持不变，因此每轮仍发送完整可独立理解的**必要**上下文，不能仅发送差分。
- 这与删除 Tavern-Helper 聊天变量是不同操作：unread_city 的权威快照必须继续正确保存。

## 兼容和验证
- 原有双主角个体叙事和手机私密信息规则不变；全知总结只能用于作者层面的情节连贯，不能让人物凭空知情。
- 对七日边界、唯一摘要、两人证据、重复 ID、旧存档迁移、模型输出校验、取消和提交失败做回归。
- 源码 PR 不意味着已发行新 PNG/本地 ZIP，也不等于完成 TauriTavern 真机验收。
