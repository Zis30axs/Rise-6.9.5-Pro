# NPC 联系申请、短信与魔裁群聊

本增量基于 PR #15 的 f84f5778106d918e6eb88b27e08e9e1343a1bda4，独立分支 feat/lite-npc-contacts-20261022。PR 以 #15 的开发分支为 base，保持依赖可审查；#15 审查合入后再整理到 lite，不能把依赖提交当作本轮新增。未修改 #16 的素材或资源包。

## 玩家流程

走近地图上的人物并搭话。已经发生的相遇由距离校验后的 encounter 动作记录。人物可在实际对白中提出加好友；模型只能引用这个人物的稳定 ID 与原始对白提出申请。手机「消息」显示申请，玩家选择接受或婉拒。接受后才产生正式联系人和关系记录。

「消息」的会话列表可选择另一主角、已保存的 NPC 或已加入的群聊。发送短信先保存，私聊为收件 NPC 请求一次模型回复，群聊按已保存计划最多依次请求三位成员。模型可按性格、当前位置和日程回应、解释忙碌或用 null 表示暂不回复。失败时保留原消息，点击重试；没有常驻 Agent、轮询或由 NPC 回复引起的递归生成。

真实内嵌手机中，从原聊天 App 打开剧情联系人会转入同一受控会话，联系人编辑仍在原 App。内嵌构建同时阻止旧聊天模型路由读取剧情联系人，避免绕过新的私密投影。未经本轮适配的独立外部手机扩展不自动获得这些入口修改。

## 受控动作与证据

模型可在普通故事协议中附加：

    <contact_requests>[{"kind":"contact","npcId":"majo-emma","evidenceId":"current","quote":"可以加个手机好友吗？"}]</contact_requests>

- kind 只允许 contact 或 group；其余字段或超过四项整轮拒绝。
- npcId 必须是当前实际搭话者；名字、立绘路径和玩家 ID 不能代替稳定人物 ID。
- quote 必须逐字等于该 NPC 已保存或本轮竖线对白中的一整句，并含相应联系或群邀请意思。current 在提交时替换为程序分配的 assistant turn ID。旁白、回忆、名字匹配和玩家内心不构成相遇证据。
- 相遇、对白证据、申请和正文进入同一候选存档；只有保存成功才发布。模型不能输出接受状态、亲密度或任意关系补丁。
- 手机确认使用严格的 resolve_contact_request 动作。申请属于哪位主角就只能在那位主角自己的手机处理；拒绝不创建联系人。
- 接受沿用人物稳定 ID，保存 sourcePersonId 与关系回执。改名、改简介保留 ID 和亲密度；同名人物不能自动合并。存档与重复请求均按稳定事件 ID 校验，不一致重放拒绝。

短信请求仍用纯 phone_reply 标签，不要求上游 Tool Calling。NPC 回复字段只有 messageId 和 text；text 可以是最多 1000 字的文本或 null。转账、位置、日历、世界行动、追加邀请和额外字段均不能通过短信回复协议执行。

## 数据与隐私

ProtagonistWorld.npcPhone 是可选、版本为 1 的增量，仍兼容原 1.12 存档。旧联系人、旧收件和双主角 canonical SMS 不被覆盖或迁移；读取旧存档不会自动创建魔裁好友或把玩家拉进群。只有实际交互才产生新记录。

NPC 地址采用稳定人物字符串，和手机主人使用的 ProtagonistId 分开。私聊以「手机主人 + NPC ID」寻址；群聊以稳定群 ID 寻址。联系人保存 ID 与来源人物 ID 可不同，手机投影通过显式映射关联，不能按姓名串线。

NPC 模型只得到自己的简要世界书、当前实际日程/位置、本人参与的明确对白、当前私聊或群聊及自己曾发送的同联系人剧情消息。不会得到玩家的普通正文、私人日记、全知周报、另一主角的私人经历或其他 NPC 的私聊。聊天记录仍保留在存档，模型窗口有界，不反复上传完整历史。

相遇、证据、申请、对白回执与短信分别设上限，达到上限明确拒绝新增而不静默覆盖旧记录。该增量不包含完整历史归档/压缩器。

## 魔裁十四人群聊

魔裁十三名少女与月代雪构成「大家的日常」的原有十四人圈子，遵循用户确认的全部幸存、既有朋友关系。素世和祥子开局均不在其中；必须先结识一位成员，由她当面邀请，再由玩家接受。入群不自动把其他十三人写入好友列表。加入一位玩家时界面显示 15 人；两位主角都加入时是同一个群的后续消息。

每次发送群消息，从当前有空的成员中随机选 1–3 人，人数不超过可用成员数，成员不重复。请求 UUID 的固定散列提供本轮抽样，完整人物顺序与每人的回复/沉默决定随原消息保存；逐人调用，每条回复先保存，再交给下一位成员。后发言者能看到本轮前面的群消息，但不能看到他人的私聊。中途失败时重试只继续未完成成员，不重新抽人、不重复已发内容，最多三人后结束，不继续自动接龙。全部忙碌/休息时不调用模型，保留暂未回复的发言。新加入者按持久消息序号查看加入后的内容，同一游戏分钟内的入群前消息也不会被误公开。

## 验证与交付边界

本地真实内嵌手机构建、vue-tsc --noEmit、14 文件 138 项定向回归及四种视口的真实手机测试通过。四种视口是 1440×900、1280×800、390×844、320×568；截图与字节记录见 outputs/npc-phone-qa/。

浏览器测试使用实际构建的 ST-iPhonie、生产手机 API、Bridge 协议解析及运行时，Tavern 宿主与模型输出是本地受控 fixture，外部模型网络请求被拒绝。覆盖接受/婉拒的运行时、保存失败重试、私聊与群聊、旧联系人入口、快速回复竞态、已读动画、刷新幂等、标题与滚动、无横向溢出和发送按钮操作。切主角、切聊天、隐藏和退出后的迟到回复在实际 Shell 生命周期单元测试验证。

没有调用真实模型、部署用户手机、覆盖真实存档、构建发行卡或合并 PR。完整前端生产构建由本 PR CI 再检；本地仅恢复了类型检查和内嵌手机需要的输入，未用占位图片冒充完整版构建。#16 正式立绘尚未接入，当前沿用已有通用呈现，不能把运行时注册当作十四套人物美术已完成。
