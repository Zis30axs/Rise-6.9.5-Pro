# 双主角与手机系统：隔离工作计划（2026-10-20）

## 与 Work 的协作边界
此 Draft PR 只维护 **长崎素世 / 丰川祥子** 双主角切换、存档迁移、跨视角手机、Appie Pay、游戏内交易及双手机 UI。市中心区、丰川家、祥子与家族和解的世界书和差分立绘已经由另一 Work 任务处理，**不在本分支重新编辑或覆盖**。独立分支 `feat/dual-protagonist-phone-economy` 从 `main@3d440d9283269f5668da941f0c03c8cd8f5fc24c` 创建。禁止自动合并或强推；Work 结束后再审查冲突。

## 用户需求及实现原则
1. GTA5 式主角切换：可选 `soyo`（素世）或 `sakiko`（祥子）；两人各自保存位置、状态、背包、手机、初始资金及个人日历，共享同一个故事世界与时钟。原作背景必须尊重 Work 新增的祥子世界书；没有用户确认的具体初始资金不冒充原作设定。
2. 强制单一事实来源：游戏中「另一主角手机」不再是独立编造的展示快照。读取该设备时由 LLM 在角色已知信息边界内补充必要内容，并以稳定事件 ID 持久化；切成设备本人后仍是相同的消息/订单/日程。
3. 偷看与代操作分离：谁发起、观察时间、访问的设备、读取内容、是否授权都留记录；代替对方发消息、下单、支付或修改日历要有可追溯日志及后果。无授权不能偷偷抹除。
4. 购物、日历、外卖应具有真实的确定性游戏内状态机，包括商品与报价、确认、支付、订单、配送/取消、日历冲突、状态恢复。LLM 仅提出结构化行为，不能通过叙事文字直接修改余额。
5. 资金从生理/行为 `player` 状态和状态面板移到独立 **Appie Pay** 账本中，`GPT Card`、`ClaudeCard`、`GeminiCard` 视为**虚构游戏内账户**，并非现实支付服务。旧 `player.balance` 严格迁移至素世账户，不丢失资金；避免已有商店、乘车、活动等扣款失效。
6. 两位主角的手机拥有独立身份、主题、应用视图；保留同一聊天 session 隔离，不能把另一个聊天或现实手机设置混进来。

## 发布体积强制门禁
**最终 TauriTavern 专用 PNG 必须严格 < 50,000,000 bytes（十进制 50 MB）。** 此限制适用于完整世界书、差分立绘、内嵌手机与 IIFE，不能只测脚本或源码大小。目标预留空间，优先图片/贴图复用、局部差分、已有手机资源、共享字体和纹理；不得为双主角复制整份手机运行时代码或额外附赠 24 MB 音效包。保持现有专用 `zTXt` 压缩及无损内容往返；不能为了缩体积删剧情或降低持久性。构建结束必须记录压缩后真实字节数、SHA-256、元数据往返和手机运行时资源验证。


## 2026-10-20 用户确认的额外能力（代号：平行人）

用户认可此前提议的 **1–4、7–8**，其中 1–4 是核心目标，7–8 是后续沉浸扩展。GTA5 式体验指的是**同一故事时间线上，两名主角拥有独立的生活**，并非复制其资源、剧情或界面。

### P0：优先实现 1–4

1. **双主角后台生活（1）：** 玩家控制素世时，祥子仍能按自己的既有日程发生合理、规则驱动的活动，反过来同理。只在世界时钟真实推进后增量结算；重试、刷新或反复切换主角不得再次抽取或重复结算。关键选择不能由后台 AI 擅自代替玩家作出；必要时使用待决事件。
2. **独立记忆、秘密与知情边界（2）：** 世界事实唯一、各自主角的所知不同。消息、目击、对话与读到的材料带来源与知情人信息。叙事上下文只能包含当前主角已知的事实，不因玩家从另一视角看到秘密而穿透到角色认知中。被偷看的设备历史本身仍为其真实拥有者的记录。
3. **偷看手机隐私与痕迹（3）：** 手机归属、场景可接触性、锁屏/解锁、是否获得许可决定允许读取或代操作的范围。仅查看和发送消息/删改日历/购物/支付分别留操作事件；未授权代操作保留可追溯痕迹及合理的被发现后果。不是“随机扣好感”的恋爱系统。
4. **游戏内电商与外卖闭环（4）：** 可选商品、报价、确认、余额校验、订单创建、配送到实际地址、收货入包、取消与退款，以及跨主角可见的收货/代收行为。所有资金只通过 Appie Pay 的虚构账本确定性结算。未确认的订单不得扣费，重复模型回复不能重复下单；日历应能记录送货预计时间。


### 父代理路由 + 按需子代理：平行叙事执行方案（用户 2026-10-20 确认）

**采用用户提出的简化架构，替代「素世 Agent 与祥子 Agent 始终同时运行」：** 当前受控主角由父代理/叙事导演处理，父代理先判断此轮玩家行动与另一主角是否存在实际交集；**有交集则父代理直接描写并处理双方，不另外召唤子代理**。两条生活线没有实际交集且另一主角确有需要生成的自主行为时，才请求**一个**子代理处理暂不在视野中的另一主角。切换主角后两者职责立即交换，绝不为某一固定角色永久常驻子代理。

**「交集」不能只理解为面对面聊天：** 见面、正在对话、共同参与事件、向对方手机发消息、共享/冲突日程、替对方下单/支付/改日历、对另一人位置或资产产生直接影响，均属于需要父代理统筹的交集；仅同在城市或单纯知道对方存在不算。交集路由优先从可验证的场景、收件人、行动目标、日历、订单与事件元数据判断；玩家自然语言意图不明确时由父代理澄清/判定，不能让独立子代理抢写同一事件。

**调度流程（设计，尚未接入）：**

1. 玩家行动绑定当前 `activeProtagonist`、`chat/session`、世界版本及游戏时钟。确定性动作先建立「待提交」状态，不修改存档。
2. 父代理检查本轮双方是否存在直接或间接交集：
   - **有交集：** 仅父代理生成玩家当前视角的剧情和双方关联的行动提案；另一位主角不会额外获得子代理生成，以免两个模型争夺同一事件的解释权。
   - **无交集：** 另一人已有的固定日程、通勤、订单配送、休息等由确定性规则结算，通常 **0 次额外 LLM**；存在超出规则表的有意义自主抉择时，才将**仅属于另一主角的已知信息**发送给子代理，要求输出结构化、可拒绝的后台行为提案（不直接写世界存档）。
3. 运行时对父代理/子代理行为做权限、地点、可接触性、资金、日历与知识边界检查，按同一游戏时钟合并为**唯一有序事件**。若目标世界版本已变化，丢弃过期提案，重新基于最新存档判定，不能覆盖玩家后来作出的选择。
4. 同一推进请求/时间区间须有稳定的 `turnId`、`agentTaskId` 和事件幂等键；**刷新、重试、切主角、聊天切换、取消都不能重复执行后台活动、付款或消息**。所有事件与世界状态成功保存后才更新两台手机。
5. 后台结果可以进入**共享世界事实库**，但不会自动进入当前受控人物的**已知事实**；Narrator 只叙述当前主角能目击、收到消息或合理获知的内容。玩家切换到另一主角时，可以回看其同一时段真实保存的经历，但绝不让另一个 LLM 生成第二套互相矛盾的历史。
6. 对于家庭和解、重大分歧等已确定为重要剧情的节点，子代理仅能建议动作或记录待决事件，不得未经玩家参与就做不可逆关键决定。

**调用成本约束：** 平常每轮仅主叙事调用；固定日常由代码推进；必要时每个独立时间窗口至多追加一次子代理决策（可合批）。不要求新 Agent 框架或长期后台循环，也不在页面隐藏、刷新期间持续消耗 API。保留当前独立叙事 API / 标签式协议及已有 `world_actions` 验证，不修改用户模型配置。未来具体次数上限可以配置，但必须避免每分钟一次 LLM。

**应增加的回归案例：**
- 素世与祥子当面交谈、聊天或同一事件：只调用父代理，子代理计数为零。
- 两人分处不同场景，祥子有可确定结算的课表：无需额外 LLM，时间与结果保存一次。
- 分离后祥子需要独立决定：子代理只收到祥子所知信息，返回经验证的行为提案。
- 子代理正在生成时，素世与祥子发生交集或用户切换主角：过期子代理输出丢弃，不污染新视角。
- 父代理与子代理涉及同一手机订单/日历/位置：同一 ID 只提交一个权威事件，并保持两台手机一致。


### P1：支持 7–8

7. **独立位置、房间、物品归属（7）：** 视角切换不传送；两位主角保留各自场景/室内位置与背包，物品交换必须发生合理的交接，不能从远处无因转移。定位与主人身份决定手机能否被偷看。
8. **手机个性化与动态通知（8）：** 主题、壁纸、应用排列与使用习惯属于各自设备；消息、订单、日历变动产生权威通知并同步角标。切换和刷新后不丢失、不重复展示通知。以共享手机代码和少量差分资源呈现，不克隆手机 bundle。

### 明确暂缓

- 暂**不追加**建议项 5 的约会邀请/失约剧情机制，建议项 6 的双向感情/恋爱数值模型也暂不立项；用户表示恋爱话题从长计议。
- 原本明确提出的**日历真实可用、时间冲突校验与日程读写**仍然必须实现，但不引入恋爱/约会预设。
- 未授权行为可以产生剧情上的**普通信任、警惕与现实后果**，但不借此默认设定两人的恋爱关系，也不自动推进亲密关系。

### 必测跨主角场景

- 在素世视角经过 60 游戏分钟后切到祥子：后台活动只结算一次；再切回素世时世界时钟不倒退，素世原有未完成任务保持。
- 祥子独自知道的家庭事件：素世的 LLM 上下文在未获证据前看不到，哪怕玩家曾通过祥子视角阅读。
- 素世读取祥子手机日历，未经许可修改：祥子本人切回时看到**同一日历更改与操作痕迹**，不得另编一个日历；后果由状态规则/上下文处理。
- 素世的 Appie Pay 扣款与外卖订单只生成一个交易 ID、订单 ID；重复刷新或重试不再扣费。祥子代收需有地点条件。
- 不同手机的锁屏、通知、主题与 Appie Pay 持有人和余额均保持独立；两台手机仍属于同一聊天世界，不混入别的聊天。
- **总发行体积门禁**仍为 Tauri 专用 PNG 严格小于 50,000,000 字节；截图尺寸覆盖桌面和手机四视口，真机验收另记。
