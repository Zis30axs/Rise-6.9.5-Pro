# 双主角各自叙事与后台日常

本次变更把长崎素世和丰川祥子接入同一套后台日常规则与个人叙事回顾。玩家控制任意一人时，另一人可在游戏时间推进后处理自己的普通日程、移动、休息、食物与简单消息；切回后，从本人已经保存的经历继续故事。两人的规则入口对称，素世也会在后台生活。

这是现有双主角、Appie Pay 与真实内嵌手机上的增量实现。按需 LLM 子代理路由仍是后续设计，当前没有第二次模型调用、额外 Agent 服务或按现实时间常驻运行的后台循环。

## 玩家如何使用

1. 用现有「切换主角」控件选择素世或祥子。位置、背包、账户、手机与故事随本人切换，世界时钟共用。
2. 在当前视角推进游戏时间。规则只结算这次实际经过的区间；在场的另一人交由当前叙事处理，分开时才独立安排日常。
3. 切到另一位主角，在「状态 → 各自的日常」查看已保存的个人经历和交流记录，然后照常点「继续故事」。读取或折叠回顾不会消费记录，也不会再次付款、发消息或推进时钟。

切到本人时，尚未完成的后台安排交回玩家，留下一次待决记录。例如公交行程尚未完成时，不会为方便切换而瞬间到达，也不会提前扣除尚未结算的车费。已发生的生理消耗和已经支付的订单继续保留。

## 已接入的行为

| 情况 | 当前规则与归属 |
| --- | --- |
| 普通日常 | 分离时按游戏时钟的绝对 15 分钟边界作决定，活动记录开始与到期时刻；素世整理文字和日常，祥子整理练习内容和日程。 |
| 休息 | 精力偏低或夜间安排短休，完成后按已有活动规则结算。未完成活动不会预支完整收益。 |
| 食物 | 饱腹不足时优先使用本人背包中的食物，或用本人 Appie Pay 下单。强烈饥饿先补餐；普通需求同时考虑既有日程。素世偏好普通便当，祥子偏好基础餐食，这是游戏规则配置。 |
| 订单 | 复用现有购物、配送、收货状态机；同一人至多保留一个进行中的补餐订单，送到下单时自己的实际地点，回到收货地点才能领入本人背包。没有足够余额时不会动用另一人的钱。 |
| 日程与移动 | 使用本人手机日历、待办与已经选择的专业课表。跨区行程沿用实际步行、公交和候车规则，按真实到期时刻完成，届时由本人支付；未到达前保留原位置与待完成行程。 |
| 学业 | 已选择专业、到达课表地点并满足时段和体力条件后，可按已有学习规则结算。不会替真实存档选择专业。 |
| 需要玩家参与的安排 | 人工日程到点可留下提醒、位置或待决记录；双方交集与识别到的重大决定（例如家族和解）保留给玩家，不由后台记录宣告完成。 |
| 简单手机消息 | 分离时晚间可发送一次普通问候，复用真实跨主角消息与发送证据；每人每日有记录，满收件箱不会越界追加。发送不代表对方已读。 |

双方在同一位置附近时，后台不会另写一条独立生活线；出行途中抵达当前玩家身边后，也立即停止选择新的后台活动。生理消耗仍随同一个世界时钟结算。

## 各自所知与共同经历

主叙事继续使用现有单次生成入口。其状态摘要增加 `narrative`：当前主角身份、本人最近后台经历、本人已留下来源的交流，以及可确认在现场的另一主角身份。不会把另一人的完整背景状态、私人日记、钱包或手机传进当前人的上下文。

本人后台经历最多取最近 6 条，每条最多 240 字；已知交流最多 3 条，每条最多 240 字。状态页回顾最多 12 条，总文字预算 2400 字。同一条自动短信的后台事件和发送证据按来源去重，避免在回顾和提示中复述两次。

共同经历的范围有意保持明确：在双方近距离共处、且本轮没有改变场景的情况下，把已保存故事中格式合法的素世／祥子对白记入两人的日记。记录表明「听到某人这样说」，不把说法变成已验证事实。普通叙述、内心活动、远处人物的对白和发生移动的复杂回合不会自动复制到另一人的故事。真实跨主角收件则在发件人侧保留同一事件的发送证据。

这套来源记录覆盖目前接入的后台活动、共同对白、跨主角短信和既有手机查看痕迹；它不是完整的全世界事实图谱，也没有补写旧相册、所有历史笔记或未接入材料的知情关系。

## 保存、迁移与重试

- 继续沿用 1.12.0 双主角状态，增加可选的 `protagonists.backgroundLife`。旧档缺少此字段时，从它当前的游戏时刻初始化，保留原位置、余额与历史，不追溯补算几十天的生活、课表或奖励。
- 后台游标必须与权威游戏时钟一致；个人活动有稳定事件 ID、已处理日程、消息日期和持久化的未完成安排。记录有界，后台每人保留至多 48 条近期事件，日记沿用既有限额。
- 一次推进中先在候选状态结算前台动作、后台生活和共同来源，再成功保存整个世界，最后同步手机。保存失败、生成被取消、主角切换或聊天切换后的迟到回复不能提交其中一部分。
- 相同已保存回合重试不会再执行其动作。刷新、只读回顾、重复切换和现实时间的天空动画不会重复结算后台活动、付款或短信。仍被故事引用的动作收据保留，防止日记裁剪破坏重试依据。
