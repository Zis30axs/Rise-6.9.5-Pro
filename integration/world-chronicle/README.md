# 全球现实纪年表（GMT+8）

该功能为《未读之城》的**离线世界背景**，不是独立新闻模型、真实联网订阅或自动发信器。数据与逻辑直接打包进 Lite 前端 JS（同时用于使用同一源码的其他构建目标），不依赖外部 CDN。

## 入口

- `src/runtime/world-chronicle-data.json`：2025-08-29 至 2026-10-31 范围内的 47 条世界史实（实际第一条为 2025-09-03），含来源、固定事实、GMT+8 日历与部分精确时刻。内容沿用已有全球大事录资料文件；它不是新的在线自动校验结果。添加条目之前应核实来源与东八区发布时刻。
- `src/runtime/world-chronicle.ts`：唯一的事件时间解锁、筛选、回执校验及存档数据解析。
- `src/runtime/bridge.ts`：只有**普通用户剧情生成**才按当前游戏时间选择待注入事件，将它们作为只读 `historicalChronicle` 数据和叙事约束给主 LLM；不会额外请求 API。手机被动回复、随机短信、人物简介和交互事件子任务不会消耗纪年事件。
- `src/runtime/model.ts`：`commitStoryTurn` 在完整剧情、世界行动、旁线和相关状态成功结算后，一并存入 `worldChronicle.handledThroughMinute`。错误、取消、模型输出无效及存档提交失败均不确认事件。
- `src/frontend/types.ts`：`worldChronicle` 是**共享世界属性**，不是四份主角的私人历史。它可选，因此历史存档无迁移要求；内部 `worldChronicleReceipt` 只用于将生成快照与最终提交绑定。

## 时间与历史准确性

全局纪年以保存的 `clock.day/hour/minute` 为准。游戏日历从 **2025-08-28** 开始，所有日期、时刻仅按固定 **GMT+8（UTC+08:00）** 解释，不使用东京时区、事件发生地时区、系统时钟、夏令时或浏览器时区。

- 已核实到秒的事件于对应时刻解锁；秒数非零时向上取整到下一分钟。
- 已知开始与结束时刻的天象在**开始时刻**解锁，并在注入时根据当前时间标记 `ongoing`（正在发生）或 `occurred`（已结束），给出已核实的计划结束时刻；不得把正在发生的天象写成已经结束。
- 已确认 GMT+8 日历日但没有结果公布时间的事件，最早在**次日 00:00** 解锁。例：世界杯 2026 冠军结果于 2026-07-21 00:00 之后可作为已知结果。
- 对转换尚不充分、原报道可能是当地日期的日级事件，保守采用标记日期**再过两天 00:00** 解锁，不假装该事件在该日零点已经公开。补充可靠发布时刻即可将其改成精确分钟，相关时间门槛会自动适用。
- 严禁向模型暴露未来史实，不能用开赛时刻得知比赛冠军，不能把世界史实改写为主角亲历。

## 触发、跳时和随机性

一次用户发起的普通剧情请求，先找出`上次成功处理时刻 < 事件可公开时刻 <= 本次请求时刻`的项目；只选择**距当前游戏时刻不超过 30 天**的事件，并从候选中最多挑选 **4 条**（优先重要性、其次较新）。没有符合条件的事件就不加入大事录提示词，也不会制造空白事件请求。

主 LLM 不必每轮全部展示新闻，只可依据人物兴趣、社交软件、电视等可信接触途径有选择地使用；允许完全没有反应。`npcReactionChance` 是非强制的叙事兴趣权重，不是程序自动抽取 NPC 已经得知的事实。离线新闻不能凭空改变天气、经济、人物状态、物品或真实世界政治。

请求中仅发送本次选中的事件。**提交成功后**游标推进到生成时的世界分钟，因此跳过数月时不会连续播报几个月前的旧新闻，也不会重放。用户没有请求时，时钟推进也不会触发 LLM。请求失败/取消不会消耗事件，同一次请求不会重复提交其回执。跨主角切换沿用同一游标。

这是一种**已注入即投递**的机制：并不强迫模型必须在正文描写事件；未在正文出现的同批事件也不会在下轮重复灌入。如需可见的新闻历史/手机订阅列表，应该新增独立、明确的世界内用户界面，不修改这份事实游标的语义。
