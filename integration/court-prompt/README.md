# 法院规则按需注入

普通剧情过去每轮发送完整法院规则。现在明确的单一日常请求只携带入口所需规则，正式庭审、跨阶段及无法确定意图的请求保留完整协议。没有增加意图分类模型、额外剧情请求、输出标签或存档字段。

实现基于 `lite@f7ac52b354edd831cd0d9ef8e3095616c2dc3fb8`；法院规则与 `53b11282` 相同。14 条原文移到 `src/runtime/court-prompt.ts`，不做摘要、替换、拼接改写，仍按原顺序插入 `bridge.ts`。原有 lawCareer 权威说明及其他故事协议始终保留。

## 选择范围

| 分组 | 原始规则 | 注入条件 |
| --- | --- | --- |
| 入口 | 法庭叙事规则、律师资格 | 始终保留 |
| 咨询 | 主动诉讼咨询 | 始终保留，普通地点突然咨询也具备完整报价、同意和收费协议 |
| 旁听 | 法院大厅旁听·自然语言行动 | 始终保留，涵盖本轮先旅行再旁听、时长和知识上限 |
| 委托 | 委托生成、特殊委托 | 涉及委托及其阶段后继时保留 |
| 受理 | 随机案件受理 | 可能受理时连同同轮庭审后继一起保留 |
| 开庭 | 开庭中、判决与和解 | 正式案件、旧职业案件或可能进入庭审时保留 |
| 和解 | 和解 | 庭审及和解阶段保留 |
| 执行 | 判决执行、刑事后果、协议履行、后续人物关系 | 庭审或已有协议、结果、待补叙、尚未结束的刑罚时保留；未来开始的刑罚也算 |

共享正在审理的案件、待确认诉状、待确认和解、旧职业案件任一存在时，保留全套规则，包括非当前主角所属案件。选择器只决定规则文字，不把另一主角的私人案情放入当前视角；`courtStoryContext`、四主角知情边界和结算代码保持原样。

委托→受理→庭审→和解/判决→回到事务所→新咨询可能发生在同一批行动中，因此这些阶段的后继闭包采用完整规则。不能等下一次请求才补充开庭限制。

只有整个请求匹配封闭的单一日常、单一咨询或单一旁听语法时才省略规则，例如“去食堂吃饭”“去便利店买瓶水”“去法院旁听45分钟”。不是发现几个日常关键词就判为非法律活动：追加子句、代词省略、陌生表达、繁体或英文等未识别输入一律全量。自然语言可执行能力不依赖这份节约词表；未命中只是不节约。法律地点（无正式案件的明确公开旁听除外）、近期法律剧情/日志及突发交互还会覆盖窄选择。

初始记忆检索返回内容时全量；原生 Tools 可能在内部追加新证据，因此预先全量；标签记忆的续写恢复全量。这样旧纠纷不会在检索回来后失去协议。

## 本地测量

实际捕获 Bridge 发往酒馆的 system 与 user 文本。修改前基线使用经 SHA-256 验证的原始完整协议替换选入部分；另用修改前 Bridge 实际生成了 5 组请求，逐字验证其余内容与当前版本完全相同。没有调用真实模型。

原始 14 条运行时字符串共 **5923 字符**，包含源码缩进、引号和逗号时为 5993 字符。完整 `STORY_PROTOCOL` 为 18452 字符，日常窄选择为 14352 字符，减少 **4100 字符（包含省去的分隔换行）**。

| 场景 | system 修改前→后 | system+user 修改前→后 | 估算 Token 修改前→后 |
| --- | ---: | ---: | ---: |
| 校园用餐 | 23994→19894 | 46208→42108 | 25298→22819 |
| 便利店购物 | 23994→19894 | 46210→42110 | 25300→22821 |
| 单独咨询法律问题 | 23994→19894 | 46209→42109 | 25299→22820 |
| 从外地去法院旁听 | 23994→19894 | 46212→42112 | 25300→22822 |
| 间接提出讨回欠款 | 23994→23994 | 46219→46219 | 25309→25309 |
| 事务所查看委托 | 24035→24035 | 45688→45688 | 25229→25229 |
| 正式庭审中接手结案 | 24035→24035 | 48579→48579 | 26312→26312 |
| 结案后普通日常 | 23994→21095 | 47523→44624 | 25758→24098 |

该固定样本下，校园用餐整份请求字符减少约 8.9%，估算减少 2479 Token。估算公式为“非 ASCII 码点数 + ASCII 字符数 / 4，向上取整”，不是特定供应商 tokenizer 或真实计费值。测量关闭长期记忆，不包含酒馆继承的预设、世界书及供应商消息封装；实际上下文和模型会改变总量。未知请求、正式庭审和原生记忆 Tools 路径不承诺节约。

## 验证结果与边界

- 最新 Lite 上 6 个持久测试套件 **125 项通过**，其中新增 60 项；另有 5 项本地修改前/后实际请求逐字对照通过，合计 130 项。定向 TypeScript 检查通过，覆盖 Bridge 的传递依赖和新增测试。
- 覆盖原文和完整协议哈希、所有分组、普通日常、间接/复合/否定/多语言请求、正式案件和公开旁听区分、待诉状/待和解、旧档、共享案件、未来刑罚、逾期/已履行条款、四主角、酒馆/Chat Completions/Responses、标签/原生 Tools 记忆后继；既有法院套件验证跨阶段结算、重复结算拒绝与旁听边界。
- `mandatory-story-tag-prompt.test.ts` 和 `mandatory-character-speech-prompt.test.ts` 中各有一条旧源码字符串断言失败；它们仍假定记忆接入前的直接请求调用写法。使用修改前 Bridge 复跑也同样失败，未为本次优化改写这些无关断言。本次新增测试直接检查实际两种传输请求和标签契约。
- 全项目 Vue 类型检查未完成：当前检出未准备完整地图、画面和手机生成资源；不把定向类型检查称为完整前端构建。未做 PNG/ZIP 发布、真实模型或酒馆/手机真机验收。
