# 角色衣柜与 Live2D 衣装联动（开发分支，待验证）

## 设计边界

- 只在纯小说模式的角色状态页提供新衣柜入口，不修改既有 3D 场景。
- 当前主角可以在实际已安装的 Live2D 套装中手动选择，优先适用于素世和祥子；艾玛与玲奈子没有可用模型时只显示衣着文字档案。
- 角色衣着记录是世界状态下的可选 `wardrobe`，兼容旧存档。Live2D 模型是外观资源而非设定的最终裁决者。
- 对于尚未有衣着记录的在场角色，实际显示成功的 Live2D 套装提供一次初始穿搭。对应剧情成功保存时才建立档案。天气、场景与时间变化沿用已保存的穿搭。
- 静态立绘的衣着由 LLM 在剧情首次呈现时自由填写。四位主角及在场的固定 NPC 共用衣着记录，后续剧情沿用已保存的内容。逐句对白可点头像查看当前说话人的衣着。
- NPC 没有玩家衣柜按钮。LLM 在本轮首次呈现衣着或发生实际变化时使用 `<wardrobe_updates>` 提议更新。
- LLM 只能提供资源包里可选择的大类别（casual/school/work/performance/formal/warm/summer），不能指定模型文件名、资源路径。服装的文字细节不限制预设款式：发型、上身、下身、内搭、内衣、内裤、配饰、外观均可逐项更新。
- 内衣和内裤属于衣着信息栏，并非默认可见信息；没有来源的信息在 UI 中显示“未记录”，不会根据 Live2D 图片臆测。

## 对象与持久化

`WorldState.wardrobe` 是可选共享映射，支持四位主角与有稳定身份的常驻人物。每位人物可有 `category`、`outfitId`、`details`、`changedTurnId`。衣着档案通过以下入口保存。

1. 主角在衣柜选择已安装资源：`wardrobe_choose` 本地世界行动。
2. 叙事返回 `<wardrobe_updates>` 后经严格字段验证，在正常剧情提交成功时写入。
3. 仅首次剧情提交利用桥接层内部 `wardrobeBootstrap` 收据补齐尚未初始化的 Live2D 人物；不会覆盖已有衣柜记录。

结构化文本示例（仅格式）：

```xml
<wardrobe_updates>[
  {"person":"soyo","category":"casual","details":{"top":"米白色针织衫","bottom":"深色半裙"}}
]</wardrobe_updates>
```

衣着更新不会替玩家做出未声明的重大决策，也不会单凭文字生成对应 Live2D 模型；找不到大类资源时前端使用现有模型回退，叙事记录仍保留。

## 验收与边界

- 运行 `npm run check`、`npm test -- tests/wardrobe-state.test.ts`、`npm run check:no-ja`。
- 旧存档无 `wardrobe` 应正常加载；主角切换回来后已选择的衣服保留；一次剧情只改变上衣应保留其他细节。
- 同一个剧情回合重复提交时不能新增衣着副作用；无在场证据的 NPC 衣着更新被拒绝；模型不能输出任意素材路径。
- 在 390×844、320×568、桌面视口验收衣柜滚动、长标签、关闭窗口后的立绘切换；反复切主角、切聊天，确认资源缓存释放不增加黑屏风险。
- 测试 Live2D 资源包禁用、空包、缺失目标类别、加载失败、重新启用和重建版本；文字衣着不能因资源缺失而丢失。
- 实机 TauriTavern、真实模型调用、完整旧功能回归未在本分支验证；不能仅以静态审查宣称通过。

## 当前注意事项

此版未实现新的服装购买、衣物背包、材质分层、刮开动画或动态生成 Live2D 资源。它是统一衣着记录、现有 Live2D 模型选择和叙事更新协议的首版，不应直接合并到稳定分支，直到执行验收。
