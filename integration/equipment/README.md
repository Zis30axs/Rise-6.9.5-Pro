# 背包装备：CRYCHIC 合照

基于 Lite `6aef686feed124ec79e626c271790a948612ea9e`，在现有背包中增加装备、卸下与效果预览。每人最多装备一件珍藏，不消耗数量、时间或体力，不主动生成剧情。自然语言通过现有 `world_actions` 的 `equip` / `unequip` 使用同一结算逻辑。

## 首版效果

素世音乐专业的数值沿用需求；祥子与非音乐专业的数值为首版设计预设，集中在 `src/runtime/equipment.ts`，便于后续调整。

| 人物 / 专业 | 音乐学习经验 | 当前非音乐专业经验 | 社交技能经验 |
| --- | --- | --- | --- |
| 素世 / 音乐 | ×1.5 | — | ×0.25 |
| 祥子 / 音乐 | ×1.5 | — | ×0.5 |
| 素世 / 非音乐 | ×1.5 | ×0.5 | ×0.5 |
| 祥子 / 非音乐 | ×0.5 | ×1.5 | ×1 |

只有装备时生效。未选专业时可持有、装备，暂不产生经验修正。其他跨专业科目以及法庭旁听不受合照影响。学习地点、耗时、精力消耗和跨专业随机结果保持原规则。

## 归属与兼容

- 新档与旧档的素世、祥子各持有一张未装备合照；重复加载不增发。艾玛、玲奈子不会获得合照。
- `inventory[].equipped` 随原有个人背包保存；主角切换沿用 `personalKeys`。后台个人视图显式传递主人身份。
- 学习进度原本允许半点；新增倍率可能产生四分之一点，因此按四分之一点精确保存。历史收益保存版本化效果 ID，卸下装备后仍可校验旧收益；调整倍率时需新增版本，不能改写既有版本。
- 社交 XP 保持整数，零头以 0–3 个四分之一点按人物和技能分别保存。卸下不会丢失已获得的零头；达到原有每日或总经验上限时不积攒超限收益。
- 同轮装备、学习、交流、卸下按行动先后确定倍率。任何非法操作沿用原有事务回滚与重复回合保护。
- LLM 只接收当前装备事实和人物描述，不能直接提交倍率或经验值。合照不能作为消耗品使用或赠送。
- 目录、装备状态和效果计算分离；黄瓜、金平糖及遥奈伪装留待明确设计，不加入召唤或传送 NPC 的行为。

## 本地验证

在安装仓库锁定依赖后运行：

```sh
./node_modules/.bin/vitest run --config vitest.equipment.config.mts
./node_modules/.bin/vue-tsc --noEmit -p tsconfig.equipment.json
git diff --check
```

本次定向检查覆盖 4 个测试文件、41 项用例：装备及卸下、四种预设、原有学习规则、零头与上限、旧档加载、跨主角与后台学习、历史收益校验、原子回滚、重复回合，以及实际背包组件的操作与保存失败反馈。

另以实际 `InventoryPanel.vue`、原有样式和状态结算运行本地隔离组件浏览器检查：1440×900、1280×800、390×844、320×568 四种视口，各验证四种人物/专业组合的装备、卸下和横向溢出，共 16 个场景。消耗品图片使用占位图；浏览器测试环境补装中文字体，不修改游戏字体或资源。
