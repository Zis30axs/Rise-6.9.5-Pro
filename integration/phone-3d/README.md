# 三款 3D 手机

用户于 2026-10-24 要求打开时放大、长按旋转、双指缩放，并按人物区分机型和手机壳。显示层采用 CSS 3D：实体圆角侧边、前后面、侧键、底部接口与镜头装饰；正面仍是原来的真实 ST-iPhonie iframe，可直接操作应用。

## 外观与操作

| 主角 | 本项目原创机型 | 机身与摄像头 | 手机壳 |
| --- | --- | --- | --- |
| 长崎素世 | Petal 6 | 圆润机身、斜列双摄、刘海 | 奶油绿花叶软壳 |
| 丰川祥子 | Nocturne Pro | 较方正的大机身、三摄、小圆孔 | 深蓝银纹壳 |
| 樱羽艾玛 | Sakura Mini | 紧凑机身、横列双摄、短胶囊 | 黑色为主，樱花粉、蓝色条纹 |

这些机型名和硬件组合是本项目设计，不代表角色的官方手机设定。屏幕内部仍使用 390×844 的稳定布局；机身长宽、圆角、厚度及装饰分别定义。

- 打开时用 460ms 从小到大并轻微转正；系统“减少动态效果”开启时直接显示。
- 鼠标或手指按住 450ms 后拖动旋转。水平可绕到背面，俯仰限制在 ±65°。
- 双指张开放大、捏合缩小。倍率状态限制在 0.6–1.8，实际大小还会按当前窗口和透视外框限制，避免遮住工具按钮或超出屏幕。也可用原有放大/缩小按钮切换显示区域。
- 快速点按和单指滑动继续操作应用；输入框内保留文本选择。旋转/缩放结束时抑制该手势产生的误点。
- 工具栏新增“查看手机背面”和“手机回正”，键盘也可操作。回正同时恢复默认大小。

## 实现边界

`src/frontend/phone-spatial-model.ts` 定义机型、圆角侧面与透视边界；`phone-spatial.ts` 装饰既有展示租约；`phone-spatial.css` 管理实体外观。背面装饰统一合成为一个平面，避免 Chromium 对嵌套 preserve-3d 的 SVG 背景裁切；侧面仍是独立立体面。

iframe 不移动、不重建、不截图替代。关闭、切换主角、切聊天和卸载时释放监听器、计时器、观察器、样式及机身。背面时使 iframe inert，防止不可见的应用控件获得键盘焦点。原宿主同步样式后，在绘制前恢复空间变换，避免短暂跳回平面。所有角度和缩放都是临时展示状态，不增加存档字段，不访问手机数据库。

机壳图案只使用仓库内静态 SVG，DOM 文本通过 textContent 设置，控制命令限于已知枚举。手机源仓库与白名单内嵌流程继续沿用；本次只修改本仓库的宿主展示适配层，不手改内嵌生成文件。

## 2026-10-26 · 3D 手机上下及左右滑动热修复

实际触摸回归复现发现，尽管触摸事件能够传入 iframe，3D 机身正反面同时使用 `pointer-events:auto; touch-action:none` 仍会让浏览器合成层把原生横向与纵向滚动锁死。仅禁用单面命中无效，两面都设为 `pointer-events:none` 后纵向滑动才恢复。与手机内容、存档无关。

现在正面和隐藏背面仅作视觉装饰，保留 iframe 中的正常 App 点击、上下滚动、左右桌面翻页；手机翻到背面后才开放可旋转的背壳命中区域。原有 iframe 文档上的长按旋转及双指缩放监听、主角机型、机身视觉和资源生命周期不变；修复只涉及世界仓展示适配层，不改手机源仓。

回归文件：`tests/phone-spatial-scroll.test.ts`（两轴手势取消与 3D 正反面命中）、`tests/e2e/phone-native-swipes.spec.ts`（原 CSS + 同源 iframe，CDP 真实触摸，1440×900 / 1280×800 / 390×844 / 320×568）。浏览器自动化不构成 iOS TauriTavern 实机验收；需用新版构建和角色卡检查。
