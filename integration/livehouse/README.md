# Live House 登记、预约与手机邀请

本轮以 `lite@f3009ff` 为基线，包含开发中刚合入的 #43 手机设置及 #39 跨视角叙事。仅改源码和定向测试，不重新打包、覆盖历史 PNG/ZIP/发行物，也不运行远程 CI。

## 玩家流程

1. 在 Live House 选择「创建乐队」，填写乐队名、本人分工，并确认本人作为创始成员。成功保存才消耗 20 游戏分钟和 3 点精力；初始成员只有本人。
2. 手机 → 消息 →「我的乐队」，选择已加入的乐队、已保存联系人、受邀分工，发送邀请链接。普通联系人可邀请；受邀者若是四位主角之一，必须已选择音乐专业。这项受邀限制不使用素世、祥子的经营资格豁免。
3. 发送只保存短信。玩家点击「让对方回复邀请」，模型依据该收件人的资料、当前会话与明确邀请返回同意、拒绝或暂缓。只有结构化 `accept` 才把此人加入名册，同时保存回复和能力面板。没有决定、格式错误、请求失败、保存失败或跨聊天迟到结果均不登记。
4. 在 Live House 选择预约，明确选择本人已加入的乐队、演出名称、游戏天数、时刻和时长。保存成功才消耗 30 游戏分钟和 5 点精力；档期必须晚于手续完成时刻，检查场地及主角成员的已有日历/当日日程冲突。
5. 手机「我的乐队」可查名册、成员能力、邀请结果和具体预约。已预约演出的主角成员还可在手机日历查看安排。

创建和预约继续保留原资格：素世、祥子无需音乐专业，艾玛、玲奈子需要音乐专业。原前端按钮限制、服务端权限、室内设施距离和精力检查均保留。普通 KTV、排练和观察不受新增登记流程影响。新 UI 默认面向小说模式；未扩展 3D 场景。

## 存档与事务

共享的可选 `WorldState.livehouse` 使用内部 `version: 1`，保存：

- `bands`：稳定 ID、玩家填写的名称、创始主角、登记时刻、已确认成员及分工。
- `bookings`：稳定 ID、乐队、演出名称、绝对游戏分钟、时长、预约人、当时确认的成员快照。
- `invitations`：发送者、稳定人物 ID、分工、原短信 ID、待回复/同意/拒绝/暂缓状态及回复。
- `profiles`：按稳定人物身份保存一次的五项能力（主唱、吉他、贝斯、鼓、键盘）。

这些记录不属于个人视角槽或 `interior.activityId`。切主角、离开房间、其他交互、日记裁剪都不会覆盖登记。登记/预约使用表单请求 ID，手机邀请沿用手机 operations 幂等机制；同 ID 不重复计费或入队，同名乐队/同人待回复邀请有独立重复检查。保存失败不发布半份状态，重试表单沿用请求 ID。

预约成员快照不会被之后的入队追写；新增成员参与后续预约。日历是预约的投影，删除日历显示项不会删除已确认的预约；重放原预约可恢复其投影，不会覆盖其他预约。后续增量预约只同步本次安排。

旧存档没有 `livehouse` 时保持原样，不从旧「成功」日志或活动标识推断乐队、成员、日期，也不追扣时间和精力。严格解析版本、字段、引用、重复 ID、能力范围及邀请短信/入队凭据；无效数据报错并保留原存档。当前上限：50 支乐队、每队 20 人、200 条预约、500 条邀请、300 份能力档案，达到上限明确拒绝，不静默丢弃已确认记录。

## 能力设定与模型边界

素世贝斯 90、祥子键盘 96、立希鼓 94、乐奈吉他 97、灯主唱 90、爱音吉他 58、睦吉他 93、初华主唱 94/吉他 90、海铃贝斯 96、若麦鼓 86；其他项目默认 25。数值属于游戏调参，并非原作公布的分数。已接入的其他常驻人物暂用固定基础值。

普通陌生人的各项能力以首次邀请的随机请求 ID 和稳定人物 ID 生成 10–90 的固定抽样，实际数值写入 `profiles`。后续重载、改联系人显示名或加入另一支乐队均读同一档案，不重新抽取。既有角色首次匹配其世界书姓名/别名，之后沿稳定 ID 保存。

模型只能对指定邀请给出 `accept/decline/later` 和短信文本，不能提交成员数组、能力数值、档期或世界行动。正文模型读当前主角相关的名册/预约，并明确要求普通聊天、叙事、`activity` 或 `schedule` 不能代替正式登记。后续普通短信的合并回复保留独立待确认邀请，不会把它们顺带关闭。

## 本地验证与限制

最终命令与结果记录在本节；测试不调用真实模型或付费 API。

- Vitest：11 文件、78 项定向测试通过，包含新增存档/表单/手机按钮/真实生命周期/受控 Tavern Bridge，以及商业区、专业隔离、短信、游戏时钟、滑动、设置和跨视角回归。
- Vue/TypeScript 静态检查通过。当前工作区只获取了所需源码/素材，私有手机生成模块使用与构建脚本一致的 `string` 类型声明参与本地检查；该声明不提交、不作为内嵌手机生产构建通过的证据。
- JavaScript 语法检查和差异空白检查通过。
- **未通过验收**：1440×900、1280×800、390×844、320×568 四尺寸浏览器实测。环境没有浏览器可执行文件，Playwright 下载的浏览器归档无法解压（`End of central directory record signature not found`），因此没有截图，也不把 jsdom 组件测试称为布局实测。PR 保持 Draft。
- 未做完整内嵌手机/发行卡构建、TauriTavern 真机或真实模型验收；未运行 GitHub Actions，提交带 `[skip ci]`。
