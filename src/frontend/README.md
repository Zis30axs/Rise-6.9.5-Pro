# Immersive Shell 前端

Vue 3 + TypeScript 的 P0/P1 原型，以全屏 Three.js 交互场景、可展开或收起的小说阅读层，以及手机、地图、日程、人物、状态悬浮窗呈现世界。界面通过独立全屏 Shell 覆盖原生聊天，接入边界为 Tavern-Helper Bridge；浏览器开发服务使用演示 Bridge。

最新目标为用户手机上的 TauriTavern：手机随同一助手 IIFE 和 PNG 内置，无需单独安装手机扩展；仍需酒馆助手及角色脚本授权。金色“手机”按钮明显常驻，后台随 Shell 连接以接收剧情消息，点击时才打开窗口。兼容的外部实例可复用。内嵌展示、剧情数据联动及 TauriTavern 真机证据分别记录，目标手机尚待导入验证。

## 开发与发布

```bash
npm install
npm run dev
npm run check
npm run test
npm run build
python scripts/build_card.py --frontend dist/immersive-shell.js
```

构建输出 `dist/immersive-shell.js`，包含 Vue、Three.js、d3-geo、CSS、处理后的地理轮廓、本项目资源及 ST-iPhonie 内嵌包；固定 banner 为 `UNREAD_CITY_IMMERSIVE_BUNDLE`。Three.js 与 d3-geo 是本地 npm 依赖，随脚本打包；程序化几何、静态降级图和内嵌 GeoJSON 无需 CDN、外部地图服务或私人素材。构建器将完整 IIFE 存入角色卡的 `data.extensions.tavern_helper.scripts`，以稳定 ID `9d9bc6da-0c08-4d1f-8d18-451c4de6e295` 替换本项目脚本，不创建第二份。

`scripts/build_embedded_phone.mjs` 从独立私有仓库 `D:\.study\ST-iPhonie` 白名单读取代码、CSS、分词和相关资源，生成 `src/frontend/generated/embedded-phone.ts` 与许可证说明；不得手改生成产物。`predev` / `precheck` 会重建默认手机包，`npm run build` 的检查步骤也会触发此过程。默认不带约 24 MB、304 项的音效包，保留手机手动导入；完整音效包属于高级构建选择，须核对最终产物，后续默认重建会覆盖预生成的非默认选择。构建机需要手机源码目录，导入成品的设备只需 PNG。应用源文件之外的私人数据、设置、密钥和聊天存档不参与打包。

## 全屏场景与阅读层（2026-10-17 改版）

- `InteractiveScene.vue` 管理 Three.js 渲染、拖动/方向键环视、点击热点、固定观察节点、暂停和释放；`scene-world.ts` 仅创建演示校园几何与观察路线。视角在眼高位置水平 360° 旋转、限制俯仰，不提供任意飞行或完整碰撞漫游。
- 节点间前进/返回是同一世界地点内的局部镜头变化。即使节点名称描述了周边建筑，也不执行 `travel`、不推进世界时间、不写存档中的 `locationId`；地图的确定性 `travel` 才执行跨地点移动，并重置对应场景观察路线。
- `App.vue` 维护 `compact`、`expanded`、`hidden` 三种阅读模式，正文按完整段落渲染为纯文本，不解释模型 HTML。回看时保持滚动位置；新回复到达只显示“有新内容”，点击后跳到最新段落。
- 同时显示一个可关闭的工具悬浮窗；桌面可拖动标题栏，窄屏限制在可用视口内。`WorldPanels.vue` / `panels.css` 提供地图、日程、人物、状态和本地演示手机内容，面板内部滚动，保留明确的确定性行动按钮。
- 真实手机通过展示宿主 API 对齐悬浮窗槽位：有兼容实例时保留原 dialog/iframe，否则启动内置后端与同源 `srcdoc` 手机。剧情连接后台进行，展示按需打开；关闭或切换工具窗只释放展示。金色入口在展开阅读和其他浮窗打开时仍常驻，显示当前剧情空间的真实未读数字；人物窗口可直达对应会话。
- `dismissOverlay` 让 Shell 父页面 Esc 先关闭当前工具窗，无窗口时再将展开阅读缩回普通阅读，最后交给生命周期退出。手机 iframe 内沿用插件 Esc 返回规则。
- WebGL 不可用、初始化失败或 `webglcontextlost` 时释放图形资源并显示内嵌静态场景，阅读、工具与热点入口仍保留；有“重试 3D”入口。静态图不是已加载的交互三维场景。
- 镜头与渲染不调用模型。观察、长椅等叙事热点只准备输入，人物问候/演示手机也只发出准备行动事件；用户确认输入并发送后才生成。地图、日程、已读、休息等明确的运行时按钮继续按 `WorldAction` 执行。

本节记录全屏界面的设计与实现。最近一次全屏街景、阅读与分层地图验收见 `integration/extensions.json` 的 `validation.fullscreenRedesignCheck`；下述连续立体地图改版的检查、PNG 部署与实机结果另行记录，不直接沿用此前证据。

## 连续地图与路段预告

`WorldMap.vue` / `world-map.css` 由 `WorldPanels.vue` 的地图分支使用，读取同一份 `ShellModel`，只通过 `ShellActions.dispatch` 执行现有地点移动。`CampusMapScene.vue` / `campus-map.css` 绘制校园连续投影；`AtlasMapScene.vue` / `atlas-geometry.ts` / `atlas-scene.css` 管理合并地理场景，`atlas-landmarks.ts` 维护 10 个程序化地标的身份、近似位置与原始来源。样式由 `shell.css` 统一导入 Shell ShadowRoot，不能仅依赖组件副作用导入向外层 document 插入样式。地图的层级、缩放、平移、朝向、地区选择与意向草稿属于界面状态，不修改存档格式。

- **连续范围。** `depth` 保留同一缩放轴：`0` 校园平面、`1` 2.5D 沙盘、`2` 虚构所在城市、`3` 省域尺度、`4` 国家尺度、`5` 世界尺度。中国与世界是同一个持续挂载的 Three.js 场景，数字 3/4/5 不对应替换三张不同地图。平面与沙盘也保留同一个校园场景节点；城市与地理场景仍以渐变衔接。所在城市未命名，不默认指定杭州；非校园/沙盘层不提供跨省或跨国 `travel`。
- **缩放与自动省界。** 滚轮围绕指针、捏合围绕双指中心连续改变范围，不需点击国家后才出现省份；视野内一级区划按投影尺寸自动加载。外国地图在省域尺度后继续通过 `zoom` 放大，平移与缩放不被重置为某个国家中心。地区列表的显式定位才调用 `focusFeature`；`view-change` 让详情跟随视野中心。原来“外国只能在独立国家层局部放大”的限制已被本次合并地图替换。
- **真实立面。** 校园地面随进度连续倾斜、轻转，建筑屋顶、完整的两侧墙面、逐层窗户和落影使用同一投影，立面高度连续增长；建筑按深度绘制。HTML 标签和 SVG 共用像素坐标投影，容器变化时重新计算，避免额外 CSS 透视让触控目标与建筑脱离。
- **地理对应。** 家乡为浙江，红色中国和浙江边界及省域示意点始终与实际相机投影对应。省域示意坐标不作为虚构城市或校园的精确位置。普通地图缩放不改变世界状态；只有返回浙江家乡入口才能继续缩到虚构城市和校园，其他国家继续浏览其区域。访问/留学仍只暂存意向，不执行行程、不改变时间和资源。
- **手势与窄屏。** 父组件统一使用 Pointer Events 管理多指中心、距离、相对角度与平移；手机双指可在同一手势中旋转并捏合，角度跨越 ±180° 时保留连续变化。画布 `touch-action: none`，外部保持普通滚动。地点/事件起手也可拖动、旋转和捏合，只有静止单指点按才激活标记，手势后的合成点击被抑制。校园标签与建筑共用带朝向的投影，地理场景通过相机旋转；键盘、画布外旋转与归北按钮提供替代操作。
- **手机标签。** 目的地按钮保持至少 44px 高，随立体进度向左右两列移开，并用细引线连接入口；短画布使用四角位置，列内至少 48px 间距，边缘至少 4px。事件只显示圆形图标，完整名称保留在无障碍名称与详情中。缩放、复位等控件移到画布外，窄屏地图与列表上下排列，搜索可代替点细小国家区域。
- **数据与资源。** `atlas-data.json` 统一保存 `countries`、`subdivisions`、`chinaCities`、`chinaMaritimeLines` 与来源/覆盖范围 `metadata`。当前 227 个国家/地区制图要素、4555 个一级区划；中国省级 34 个，浙江地级 11 个。国家/地区数不等于主权国家数，少数特殊区域没有 ADM1，单区域记录不意味着真实存在内部分省。全球数据来自 Natural Earth 10m，中国完整轮廓、省级与浙江地级来自 DataV.GeoAtlas；来源、简化和归并见 [`../../assets/map-sources.md`](../../assets/map-sources.md)。省份显示不意味着已实现该省的城市、道路或出行内容。
- **同场景相机。** 正交斜视相机使用同一经纬平面，地表顶点有浅起伏，国家、省界、地标与红点共享投影。起伏按少量山脉位置做艺术化示意，不能称为真实 DEM。`panBy` 平移地理中心，`setZoomAnchor` 保留指针/双指下的地理点，`focusFeature` 显式定位并返回建议 depth/zoom，`resetView` 恢复家乡路径；`pickAt` 根据实际 canvas CSS 边界换算射线。地理场景不再叠加父级 CSS 平移/缩放。
- **LOD 与清理。** 只在进入地理范围时初始化地图 WebGL；省级几何按可见包围盒和像素尺寸加载，最多 260 个可见、缓存上限附近 360 个，长距离平移回收不可见缓存。隐藏时停绘，场景按需请求帧。永久卸载释放材质、几何、渲染器和 WebGL context；初始化失败或 contextlost 时使用内嵌 SVG 备用地图，contextlost 降级不再强制失去上下文。
- **比例尺与水印。** 比例尺使用当前中心附近的投影、纬度及地球球面距离近似计算，以约米/公里显示；该工具不是精确导航。左下按用户要求显示本地 `assets/openai-mark.svg` 与 `Open AI Map`。资源不调用在线地图、设备定位、远程贴图或模型。
- **中国方面呈现。** 以 DataV 完整 CHN 外框及 34 省级数据呈现台湾、香港、澳门与南海诸岛，台湾为 `710000/CHN`，不独立出现在国家列表。`chinaMaritimeLines` 的一个 MultiPolygon 含 10 个狭长片段（南海九段、台湾东侧一段），以红色不可选择辅助几何显示，定位中国时包含其最南范围。中国国家面、红边、一级区划和拾取按 CHN 优先，其他图源重叠部分由数据预处理裁去。科索沃归 SRB、索马里兰归 SOM、北塞及缓冲区归 CYP、关塔那摩基地归 CUB；后续涉及归属继续核对中国方面资料，未核实特殊区域不擅自归并。这是用户指定呈现及资料处理，不是官方标准地图认证。
- **架空苏联。** 国家要素 `SUN` 展示“苏维埃社会主义共和国联盟”，由十五个前加盟共和国轮廓求并集形成。只确认架空版图存在，不自行推断历史年代、制度或剧情；这项改编不能当作现实当前国界声明。
- **演示人物定位。** 默认关闭的图层只读取本组件明确的 `personWorldLocationRefs` 记录，并同时检查联系人关系至少为 10。样例仅林同学在图书馆；没有记录或关系不足不显示。不解析人物状态文案推断位置，不将其冒充已接入真实世界人物位置或手机数据。
- **确定性事件与结算。** 地图目的地预告、路段标记和详情读取运行时 `getRouteOutlook(state, targetId)`；基础移动为 15 分钟、5 点精力，事件的 `extraMinutes` 追加到时间。`reduceState` 执行 `travel` 时重新按同一当前状态计算并写入日记，不在地图本地复制结算规则，不通过刷新或查看标记重新抽取结果。仅查看事件详情、缩放或切层不消耗时间、不调用模型。

事件图标按完整 44×44px 触控范围避让地点标签及其他事件，必要时用虚线连接原路段。手机缩放按钮靠左，避开右下角的独立恢复入口。访问/留学意向属于界面草稿，不能锁定普通地图的浏览范围。

运行时使用 `atlas-data.json`。旧 `prepare_map_data` 保留为新 atlas 构建的兼容入口，`map-data.world` 也同步 atlas 结果，不再按旧 Natural Earth 110m 流程重建；更新数据后应核对两处世界归属一致。

地图实现范围与验收结果分开记录。30 / 22 / 8 / 15 属于早期全屏布局，30 / 24 / 8 属于此前连续立体校园地图；一体地图的独立验收见 `integration/extensions.json` 的 `validation.rotatingAtlasCheck`。这些地图与旧手机托管结果均不代替最新内置手机的检查。

## 设计边界

- 场景、地图、日程、NPC、个人状态与演示手机读取同一份 `WorldState`；示例内容不属于正式设定。真实手机状态由 ST-iPhonie 独立维护。
- 真实手机在 Shell 内显示：优先复用父窗口兼容 `STiPhoniePanelHost`；否则启动内置父页后端并创建同源 `srcdoc` 手机。后台随 Shell 连接、窗口按需展示。`mount(anchor, { onClose })` 将非模态 dialog 定位到 `[data-unread-city-phone-slot]`，返回 `release()`、`sync()`、`focus()`。外部实例只借用展示，不转移所有权；本项目创建的手机实例和资源由自己的生命周期清理。
- Tavern 模式使用真实手机槽位，`phoneStatus` / `phoneError` / `phoneSource` 区分等待、可用、失败与来源。`WorldState.phone` 作为已校验的剧情收件台账；`STiPhonieStoryHost` 向真实手机投递并回传已读。真实前端数字角标来自当前剧情空间快照，连接未完成不伪装为已同步。当前开场示例消息仍明确标示示例，普通浏览器 demo 不作为真实链路证据。
- 内置版在加载、聊天切换、重绘时不自动调用模型、声音、配图或自动同步；用户手动功能保留原流程。复用已有扩展时不静默改写其配置。所有付费或外部服务测试仍须有对应任务授权。
- 内置脚本不注册扩展 `manifest.generate_interceptor`，不能声称原生 prompt 的标签剥离行为已保留。手动手机发送与设置/API 仍在，尚未实际调用模型验证；源码边界见 `assets/embedded-phone-sources.md`，不宣传手机全功能均已验证。
- 关闭手机悬浮窗、插件关闭回调和 Shell 父页面 Esc 均先回场景，世界进度保留；其他悬浮窗同样先关闭，展开阅读先缩回普通阅读，最后才退出 Shell。手机 iframe 内部 Esc 保持插件原有返回规则。切换面板、退出、切换聊天与脚本卸载均释放手机展示控制，恢复原生手机的普通打开方式。
- 正式模式通过酒馆助手取得当前聊天、聊天变量与生成接口；缺少助手时应给出明确状态，不能悄悄冒充已经接入酒馆。
- 角色脚本获准启用后会校验并自动尝试进入有效单人聊天；退出后可使用“进入未读之城”重新进入。模型叙事要求酒馆选择 Chat Completion（`mainApi = openai`），该值是接口类别，不限定供应商。
- Shell 进入、退出、重复进入和脚本卸载均清理自己的挂载、样式与会话监听，不删除原生聊天 DOM。恢复入口包括 Esc、Shell 内退出、Vue 外独立“恢复酒馆”按钮，以及助手的“恢复原生界面”脚本按钮。
- 退出和聊天切换使当前生成失效；提交前核对当前会话，阻止旧回复写入另一个聊天。
- 取消只尝试按生成 ID 停止本请求。助手极早取消竞态下，上游请求可能继续；迟到结果仍丢弃，不全局停止其他脚本或原生聊天生成。
- 叙事保存在聊天变量 `unread_city.story`，不写原生聊天楼层；模型文本使用纯文本渲染。
- 演示存档只在内存中保留，刷新清空；真实模式通过酒馆助手聊天变量持久化。切换聊天后关闭 Shell，在目标聊天重新进入。
- 当前只承诺 V2 数据封装；需预装酒馆助手并授权角色脚本。助手上游依赖不属于本项目的单文件资源。

## 扩展联调范围

本机环境为 `D:\SillyTavern`（维护快照 1.18.0），已发现的手机安装在 `data/default-user/extensions/ST-iPhonie`（0.7.83-fish-mobile.5），助手安装在 `public/scripts/extensions/third-party/JS-Slash-Runner`（4.9.1）。版本只用于排查环境差异，以本人这套环境的实际行为验收，不要求为达到某个版本数字升级。安装清单与边界见根目录的 `integration/extensions.json`。

## 剧情手机契约（2026-10-17）

世界侧只通过窄接口访问真实手机，不直接读写其 IndexedDB：`STiPhonieStoryHost.bind({ sessionId, chatId, label, contacts })` 返回 lease，提供 `sync({ contacts, messages })`、`snapshot()`、`subscribe(listener)`、`openContact(npcId)` 与 `release()`。联系人为 `{ id, name, description }`；消息为 `{ id, npcId, text, at, read }`，`at` 保留世界时间。快照含当前 `sessionId`、`unreadTotal`、联系人及会话 ID、已读事件 ID `receipts`。

`sessionId` 对 `JSON.stringify([avatar, chatId])` 求 SHA-256。剧情空间在手机原有账户存储内独立分区，旧 `card:` / `group:` 空间不迁移、不覆盖。NPC 的稳定 ID 用于映射，不能凭同名合并不同聊天。退出释放本次绑定，切换与异步回执均核对拥有者和当前会话。

目前真实手机联系人仍要求 ID 最多 80 字符、名称最多 40 字符、同一剧情空间显示名唯一且不能为 `me`；世界存档容许的范围更大。超出手机限制时保留世界存档并显示联动错误，不自动截断、重命名或合并 NPC 身份。

真实生成只接收 `{ "story": "正文", "phone_messages": [{ "npcId": "lin", "text": "消息" }] }`。解析器检查字段、长度和已有 NPC 白名单；无效回复整轮拒绝。Shell 为收件生成事件 ID，先将正文和收件保存进 `unread_city`，成功后才能调用 `sync`。同一事件重试同步不重复投递；生成等待期间读回执必须合入最新世界状态，不被生成前快照覆盖。

手机真实会话的读状态回填 `WorldState.phone.read`，首页、联系人列表或收起的会话不自动读。前端入口使用 `[data-phone-unread]` 显示数字，读完移除角标；人物页“查看某人的手机会话”直达同一真实会话。优先验收 320/390 像素布局、至少 44px 点击区域、常驻入口和独立恢复按钮。

本轮范围是剧情收件与已读回传；手机手动发信自动推动世界、原生聊天楼层双向同步、真实模型和手机 TauriTavern 真机均不能由本地测试推定。`validation.phoneStoryLinkCheck` 单列本轮结果，既有内嵌手机/地图记录继续作为历史证据。
