# 2026-10-19：结构化模型行动与带走物品

最新人物更新（1.11.0）：`characters.ts` 校验新建/编辑人物，固定本地portraitId、sourcePersonId与isMain；`save_contact` 同步联系人、人物档案story及journal，重复保存不重复登记。旧contacts补稳定默认立绘，其他进度保留。`commitStoryTurn` 为新出场保存可选participantIds，不改旧正文。`character-context.ts` 以目标人物编号优先提取相关对话，旧记录兼容名称匹配，最多6条/2400字符；`contact_introduction` Bridge模式只返回<=500字简介，拒绝手机消息与状态动作，用户再次保存后生效。

更新：按钮交互由生命周期先在副本上预结算一次、显示短进度，再以80%概率询问是否探索事件。接受时，Bridge通过专用 `StoryGenerationOptions.kind=interaction_event` 传入预结算状态与数据上下文，追加事件约束；必须有实际影响的world_actions，原操作不可再次结算。生命周期在最终合并时比较实际游戏字段，拒绝无效果事件。原动作与事件同一次保存，失败不写入，拒绝事件时仅完成原动作。临时选择/动画不改变schema；普通send保持既有完整模型行动，不再抽取事件。

本节优先于下文历史的按钮专属结算说明。`story-protocol.ts` 保持旧JSON兼容，新增可选 `world_actions` → `GeneratedStory.worldActions`。`story-actions.ts` 严格校验12项以内行动：travel、rest、service、buy、pack、takeaway、use、gift、interact、study、schedule、complete_schedule、relationship、activity。只允许固定字段、已知地点/服务/商品/学科及既有联系人，不接受任意补丁。rest支持1–10080整数分钟，study支持15–240整数分钟。

`applyStoryActions` 在副本上依次结算；`commitStoryTurn` 先检查重复ID及行动指纹，再执行行动并验证最终场景中的空中事件，最后合并正文与手机消息。生命周期保存成功才发布新状态和同步手机。行动回执指纹保留到对应剧情被裁剪，防止日记轮替后重放。没有新增持久化字段，schema仍为1.10.0。

便利店普通购买不变，食品加价打包为每份2元；地点食饮使用固定 `takeaway-服务ID` 物品，通过服务目录生成营养与使用时间。打包只扣款入库存，消费才推进用餐时间和改变身体数值。gift扣除实际使用单位、更新既有联系人的亲密度并写日记，不给玩家重复营养收益。`location-links.ts` 提供显式双向邻接关系，房间与父地点进出复用既有旅行规则。

# P0/P1 状态运行时

`location-services.ts` 统一维护已有地点的服务、营业时间及可执行性。`location_service {serviceId}` 从固定目录读取价格、时长和效果，检查当前地点、非室内、完整服务时长是否仍在营业段内、余额、精力和最大天数；忽略外部传入的价格/效果。跨午夜营业按连续时段处理，全天场所没有午夜截止，恰好在关门时完成允许。预览和提交共享规则，营养只结算一次，净变化与日记随同一个状态保存，不调用模型、不增加库存、不改存档结构。书店原有 `read_subject` 同样要求在营业时间内，并可完成该档最长时长。

Bridge 的 `venue`、`locationServices` 和 `serviceAlternatives` 提供当前服务状态与同类地点此刻状态；后者不保证到达时仍营业。现有 `store` 只表示便利店货架，不能代替所有地点的服务判断。模型不重复已有 `journal`，可以通过本轮 `world_actions` 发起新交易和活动；室内位置必须对应实际可到达房间。

运行时维护 `WorldState`，通过显式的 `WorldAction` 推进时间、切换地点、更新手机已读状态、日程和空中事件。前端的六类面板读取同一个状态源，Vue 组件不各自维护互相冲突的世界存档。

状态类型目前在 `src/frontend/types.ts`，初始示例数据和纯状态转换在本目录实现。正式接入后，Bridge 将状态写入当前聊天的 `unread_city` 变量；其中 `story` 数组保存界面内的玩家输入与叙事。原生聊天楼层不受这些界面内记录更新。

当前状态版本为 `1.10.0`。`parseState` 严格校验 `1.0.0` 至 `1.9.0` 各版本的已有字段。1.9 单科存档把原科目点数完整迁入该专业的多科列表，其他课程从零开始；旧 lastGain 新增字段为 null，不伪造历史随机结果。更早版本的 academics 仍为 null，由玩家选专业，不推断或追补学习点。旧版本逐步补齐室内记录、身体状态、背包与精神；精力保留两位小数。时钟、人物、手机、原日程、日记、正文、步行位置和飞机记录保持；损坏字段直接报错，不用初始状态覆盖。

`campus-interiors.ts` 是三种示例校园室内的共同事实来源，保存房间、室外入口、室内边界、家具碰撞和互动点。`interior` 为 `null` 或 `{roomId,x,z,yaw,activityId,lastRest,lastStudy}`；进入时保留室外 `scene`，权威 `locationId` 改为房间 ID，离开时恢复原来的室外位置。入口要求距离 5 米内，交互要求 3 米内；室内坐标必须可行走，房间与返回位置必须一致。室内不能执行室外行走、搭话或直接旅行，地图提供先离开的明确入口。

`enter_interior`、`leave_interior`、`interior_walk` 和普通 `interior_interact` 均为显式操作。整理书桌与浏览书架按固定分钟和精力结算，零成本观察连续点击同一物件不重复写日记；耗时活动直接显示完成结果并保留草稿，零耗时观察才准备后续叙事；点击“继续故事”才调用模型。床铺改用 `interior_rest`：短休 15–30、中休 60–120、长休 420–540 分钟，选定后均匀随机抽取一次整数分钟，短/中休恢复 `floor(minutes * 0.4)` 点精力，长休恢复至 100。实际恢复量受精力上限约束，与时长一起保存在 `lastRest: {optionId,minutes,energyRecovered}`，同时写入日记；取消、刷新、展示活动或后续对话均不重新抽取或结算。行走保留记录，其他互动清除最近休息记录。床铺不准备输入或请求模型，不覆盖玩家草稿。室内上下文使用实际已结算结果，不把室外行人当作在场人物。室内暂停随机飞机检查，模型上下文明确天空不可见；若回复仍提出飞机事件，整轮拒绝。

`airTraffic` 保存累计次数 `sequence`、下次环境检查触发时间 `nextAmbientAt`、冷却截止时间 `cooldownUntil` 和最近航班 `lastFlight`。时间为真实时间的毫秒时间戳，独立于剧情时钟；最近航班含稳定 ID、来源 `ambient`/`story`、起始时间、固定 40 秒持续时间和 0–3 航线索引。视觉是否仍在经过由绝对时间推算，刷新、隐藏与重新挂载不重置航班。初始化后首次环境事件安排在 45–90 秒，之后每次事件安排 180–360 秒后的下一次；后台恢复不补发积压航班，180 秒冷却同样约束对话触发。

模型输出负责叙事，不负责任意改写数值，也不作为可执行代码或自动状态补丁。固定 JSON 协议保留 `story` 和 `phone_messages`，可选 `world_events` 最多允许一项 `{"type":"airliner_pass"}`。只有运行时可以分配 ID、航线和时间。模型上下文包含当前客机与历史、累计次数和冷却状态；冷却期间明确禁止提出新客机。格式不符、未知事件或冷却违规时，正文、手机消息和事件整轮拒绝。接受的剧情事件与正文一次保存，固定助手回复 ID 派生航班 ID 与日记 ID，重复提交不重复起飞。

状态转换完成后再传入叙事上下文；生成期间的退出、聊天切换、失败和迟到回复由 Shell 会话边界处理，不能把结果提交到其他聊天。

当前桥接仅支持单人聊天，叙事生成要求 SillyTavern 的 Chat Completion 接口（`mainApi = openai`，不限定供应商）。取消先使本次结果失效，再尝试通过生成 ID 停止本请求；助手极早取消竞态下，上游工作可能继续，但结果不得提交。不会调用全局停止生成来影响其他脚本或原生聊天。

这是原型运行时，示例人物、地图、日程和数值不等于完整校园模拟。复杂 NPC 自主行动、全量日程规划、通用事件去重与历史存档迁移，需各自实现与验收；`src/schemas/` 中旧协议草案不会自动约束运行时。

长椅热点复用 `wait(15)`，程序结算 15 分钟/至多恢复 2 点精力，不准备对话；地图旅行和状态等待原有程序规则保持。自由输入可通过结构化行动推进指定分钟或完成活动；严格回复协议继续拒绝 clock/player 等任意补丁。

学习使用 `interior_study {interactionId,optionId,subjectId}`，书店使用 `read_subject {optionId,subjectId}`。短时15–30、中时60–120、长时120–240分钟，基础精力消耗 `ceil(minutes/6)`。共享 quote 在抽样前检查地点、距离、学科、上限和最坏情况下的精力成本。室内实际结果保存在 lastStudy，全局学科结果保存在 lastGain，和时间、身心、日记一起事务保存。旧 study-shelf 仍是十分钟浏览，新增 study-reading 才是选科学习。旧无记录的课堂/自习锚点保持历史半小时含义；刷新、场景渲染与后续对话仅读取。行走保留学习记录，其他物件/床铺活动清除；lastRest与lastStudy不得同时非null。

交通由 `transit.ts` 统一站点、车型、路线和返程规则。新增 `transit:{sequence,lastRide}`，收据含唯一ID、车型、起止站、分钟、票价与到达时间。`ride_transit` 只允许室外、站点6米内、合法车型/路线及余额充足时操作，一次保存时钟/余额/scene/地点/收据/日记。模型只接收已结算事实，不能发起乘车事件。普通travel可到原南门站，但远目的地或原校园街区坐标范围外（含city-roads）必须乘车返程，防止走出命名区域后普通travel绕过返程。远区间暂在校园换乘。旧版迁移只补空交通状态，不重算历史。

## 专业、课程表与跨科阅读（1.10.0）

academics.ts维护8专业×3课程，各科有120/360/720点的三个具体目标。choose_academics只选专业，生成三科零进度与确定性周课表（Day1为周一、每科每周两节90分钟）；重复确认同专业不重置。课表不覆盖旧schedule，查看课表或完成待办不发学习点。

academics.subjects最多24科，各科用0.5点步长独立累计。教室限本专业，图书馆和书店可读其他专业课程。本专业实际每分钟1点；跨科一次抽取25%灵感（×1.5、精神+3压力−2）、25%困惑（×0.5、额外精力−3精神−4压力+5）或50%普通（×1）。这些额外效果叠加基础学习消耗；确认前要求可支付最长时间加可能的额外3精力。lastGain包含科目、实际分钟、获得点数、该科累计、完成时间、outcome、channel、interactionId以及精力/精神/压力净变化。保存失败不替换界面状态；刷新不重算。对话、免费观察、整理、十分钟浏览和日程不加点。
