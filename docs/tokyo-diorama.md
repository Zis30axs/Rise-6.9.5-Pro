# 东京微缩城市沙盘

## 旧版审查

以 lite 的 90e36303 为基线。按原地点登记和默认矩形计算，东京有 96 个可选目的地，其中 60 个涉及选框相交，一共 139 对。旧点选先吸附 36 像素内的标签，再在高度 8 的平面上找最近地点，框线却绘在高度 0.7。放大后，楼顶、门口和真正收到点击的地点会分离。此前独立网页还使用多幅预渲染分区图，转区时相邻地物无法保持连续。

## 城市与建筑

沙盘入口沿用角色卡的 WorldMap 和 CitySandboxScene。以原地理数据确定各地点所属区域和大致方位，再将入口落实到同一套街廓与路缘。校园、低层住宅、池袋商业中心、新宿、神田川河岸、机场和山地共同占用一个世界坐标系。跨城距离经过压缩，模型用于叙事导航。原地图坐标、人物位置来源和旅行耗时仍由各自的原数据负责。

道路与人行道沿同一条折线展开，桥梁连接两岸实际交叉口。公园保留多边形边界、步道、树冠和入口。高尾山以连续高程过渡，山道接回车站。街边住宅与商店按所在道路调整朝向和退界。住宅有阳台和坡屋顶、商店有雨棚与门面，办公楼使用玻璃幕墙和退台。Sunshine City 的主塔、商场裙楼、天文馆圆顶与水族馆顶层设施组成一个设施。CiRCLE、丰川总裁楼和若叶睦家沿用项目的模型资源。材质批量合并，逐三角面保留地点归属。

## 点选和出行

每个原目的地 ID 映到一个物理场所。楼体、屋顶、公园步道及入口在射线命中后返回最前面的可见场所，背景楼栋可以遮挡后方地点。甄别同楼内部目的地使用详情面板。远景优先保留地标、当前主角和所选地点，近景再显示附近标签。搜索支持地点名、片区名、内部设施以及已登记的居民住宅别名。主角定位只移动镜头。单击看详情，双击聚焦，鼠标滚轮或双指缩放，单指平移。气象和俯仰切换均复用同一模型。

从门口走到路缘，经街路图到达目的地。也能指定其他起点查看沿途环境。实际出行始终从主角存档位置出发，小说模式继续通过原 novel_travel 事务核算耗时、精力和票价。移动镜头、切换子目的地及查看路线均不结算。

## 实测与构建

本地检查覆盖 96 个目的地、81 个物理场所、921 个装饰地块与 590 段车道或步道。给每组建筑和装饰地块做多边形相交检查，同时检查与行车道的冲突。逐组发射场景射线，还对全城道路可达性、含六座桥的街路图、旅行报价与实际扣时、手机双指与拖拽后防误触进行回归测试。桌面浏览器与 390 × 844 手机视口验证了搜索、镜头聚焦、楼内选择和路线。验收浏览器因 WebGL 不可用，实际显示使用同一三维网格的逐三角形深度缓冲渲染。浏览器还执行了从最终 PNG 提取的角色卡脚本，从纯小说模式打开地图，预览南门至阳光60展望台路线，按原出行交互确认后，时钟从 17:20 到 18:08，主角定位随之转到展望台。调用 SillyTavern 的 PNG 解析和写入函数，用默认 Node 堆完成 V2 导入、V2/V3 重写、V3 重读，814 个世界书条目与同一角色脚本得以保留。手机尺寸测试未涵盖 iOS 真机或 TauriTavern。

在现有工程准备好角色美术和相邻 ST-iPhonie 仓库后，本地执行以下命令。第一项生成正式角色卡用的完整应用，第二项将完整角色前端、东京模型、场所、地图头像、素世模型和小说插画嵌入单张角色卡，第三项生成同组件的网页入口及自包含 HTML。可携带版在打包时合并重复字节，使用原插画的缩小版本。东京地图无需额外文件。外地原始三维模型、高清角色图和其他大媒体可在酒馆原生界面安装同次构建生成的 unread-city-lite-assets.zip。需要把外地大模型也内嵌时，可为第二项附加 --all-media；酒馆重新读写这种大卡需要更多内存。角色卡沿用项目的 Tavern-Helper 环境，需要支持 DecompressionStream 的现代 WebView。

```sh
npm run build
python scripts/build_diorama_card.py
npx vite build --config examples/tokyo/build.config.mts
```

主要回归用例位于 tests/tokyo-diorama.test.ts 与 tests/tokyo-diorama-input.test.ts。
