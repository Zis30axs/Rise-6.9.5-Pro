- **先入档再投递。** 程序生成事件 ID，将正文与剧情收件同次写入 `unread_city`，保存成功且会话仍有效才交给手机。真实手机按事件 ID 幂等处理，重开、重连或刷新不能重复造联系人/消息。同步失败保留已提交收件以便重试，不回滚或覆盖原历史。
- **窄接口与状态职责。** 世界只调用 `STiPhonieStoryHost.bind` 及 lease 的 `sync`、`snapshot`、`subscribe`、`openContact`、`release`；不绕过手机接口写 IndexedDB。世界的 `phone` 是剧情收件台账，手机维护真实联系人/会话，快照的 `receipts` 仅将对应剧情事件标记为已读。生成进行期间也要合入最新读回执，回复提交不得使已读退回未读。
- **移动操作。** Shell 启动后连接手机后台，窗口仍由常驻按钮或人物快捷入口按需打开。数字未读角标来自当前剧情空间的真实手机快照；只打开首页/联系人列表或收起手机不清空未读，进入对应会话才回传已读。优先保持 320/390 像素触控、44px 入口、常驻手机与独立恢复按钮可操作。
- **切换与清理。** 退出释放当前剧情绑定并保留原生恢复；切换聊天使旧生成、旧手机绑定和迟到回执失效，任何旧结果都不得写入新聊天。手机后台与展示所有权继续遵循内嵌/外部实例规则。
- **范围与证据。** 本轮为剧情收件 + 已读回传，不宣称手机手动回复已推动世界、原生楼层双向同步或完整双向生成。真实模型未调用；本机浏览器测试与用户手机 TauriTavern 真机分别记录。自动化、最终 PNG 和本机酒馆结果待实际检查后填入 `phoneStoryLinkCheck`，目标手机继续待用户导入。
