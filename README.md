# 未读之城 / Unread City

面向 SillyTavern 的私人、可扩展人生模拟世界工程。源码分模块维护，交付时将基础卡、世界书和沉浸式前端脚本封装成 **一张 Character Card V2 PNG**。

当前版本是 **P0/P1 交互原型**：全屏 3D 校园背景、可展开和收起的小说阅读层，以及手机、地图、日程、人物和状态悬浮窗。已有基础卡文案和开场仍包含占位内容；原型中的人物、地点和数值是交互示例，不代表已经确认的正式世界设定。2026-10-17 已完成前一阶段的全屏街景、阅读层、分层地图与真实手机托管验收；最新可旋转的一体全球地图已通过检查并更新到独立联调卡。本机酒馆已通过真实模型两轮短场景、NPC 手机收件及已读回传，结果见文末；手机 TauriTavern 真机仍待验证。

**最新手机接入方式（2026-10-17）：** 针对用户手机上的 TauriTavern，ST-iPhonie 随同一个酒馆助手脚本内嵌进 PNG，无需另外安装手机扩展。Shell 进入后连接手机后台，同步当前剧情的联系人与收件；点击常驻金色“手机”按钮才展示窗口。酒馆助手仍需安装并授权脚本。剧情联动本轮验收单列于 `validation.phoneStoryLinkCheck`，手机 TauriTavern 真机导入与运行仍待验证。

## 当前界面与操作

- 背景是本地 Three.js 渲染的程序化校园场景，铺满屏幕。本轮按用户明确的“自由移动”要求改造：普通正文且未打开悬浮窗时显示“自由行走”入口，点击收起正文；专注阅读时也可用“收起正文”进入行走。手机用左侧摇杆向任意方向连续行走，另一只手在右侧专用环视触控区或空白场景画布拖动环视；电脑聚焦场景后用 W/A/S/D 行走，方向键或拖动环视。水平可转一周，俯仰有限制。场景仍是程序化交互演示，尚非完整开放世界。
- 自由行走受建筑与障碍物碰撞、场景边界和台阶地面高度约束。松开控制、返回阅读、打开手机等悬浮窗或切到后台时停止移动；关闭悬浮窗后可在原来的行走位置继续探索。当前步行位置、朝向和人流种子随聊天存档，重新进入后恢复；地图“前往”会换到该地点的起点。
- 步行进入图书馆前庭、商店门前等区域，会更新权威当前位置；下一轮剧情收到户外环境、附近地标与行人信息。步行本身暂不推进世界时间或扣除精力，地图“前往”继续按已有出行规则结算。生成剧情时暂停行走，避免模型依据旧位置作答。
- 小说正文默认在屏幕下方，以完整段落连续显示；“专注阅读”展开阅读层，“收起正文”让出背景。回看旧内容时，新回复不会拉走滚动位置；点击“有新内容”回到最新段落。若旧世界书使回复夹带语音标记，阅读层会收起重复的语音元数据并保留独有台词，原始存档文本仍保留。
- 手机、地图、日程、人物与状态都以可关闭的悬浮窗打开；桌面可拖动标题栏，窄屏按可用空间显示。金色“手机”按钮在普通阅读、专注阅读和其他浮窗打开时都常驻。已有兼容 ST-iPhonie 实例时复用，否则加载随卡内置的真实手机；收起或切换窗口时释放展示控制。
- 点击场景热点可以打开对应窗口，或将观察意图填入行动输入；长椅休息直接按 15 分钟结算。整理书桌、温习、自习和浏览书架也直接完成，不准备对话、不覆盖草稿。观察与交谈确认“继续故事”后才发起叙事生成。地图、日程与资源按钮执行明确标示的本地操作。
- Shell 父页面按 Esc，先关闭当前悬浮窗；无悬浮窗而正文展开时，先回到普通阅读；再按 Esc 退出到酒馆。手机 iframe 内仍沿用插件自己的返回规则。独立“恢复酒馆”按钮继续可用。
- 不支持 WebGL、初始化失败或绘图上下文丢失时，改用内嵌静态场景，保留窗口、阅读、热点和旧观察点切换入口；可点击“重试 3D”。静态降级不提供自由 3D 行走。场景绘制和移动操作不调用模型。

2026-10-17 自由行走版已完成：类型检查/构建、75 项单元、13 项 Edge 定向浏览器及 8 项 Python/PNG 检查通过。已更新本机酒馆既有联调卡，安装脚本与最终 PNG 逐字一致；手机 TauriTavern 真机仍待验证。具体证据见 `integration/extensions.json` 的 `validation.freeMovementCheck`，历史验收不计入本轮。

## 地图与出行

地图保留 **校园平面 → 2.5D 沙盘 → 城市 → 所在区域 → 世界** 的连续缩放。中国与世界合为同一个持续存在的地理场景，缩放、平移和旋转只改变相机；放大到哪里，就按该处范围自动显示国家和省级边界，不要求先点击国家。滚轮围绕鼠标位置缩放，手机双指同时捏合和旋转，单指拖动平移；画布外保留 `+` / `−`、旋转、归北、复位和返回家乡入口。地图外仍可正常滚动悬浮窗。

校园平面与沙盘显示同一组可达地点。地面连续倾斜，建筑升起后露出完整墙面、楼层窗户与投影；旋转时建筑、入口、标签与投影保持对应。地点标签随进度移向两侧，以细线连接入口，较矮的画布使用四角布局，按钮保持至少 44px 高。路段事件用圆形图标显示，点开查看详情。从地点标记开始拖动、双指旋转或缩放也可以操作地图，完成手势不会误触旅行。

城市层是虚构布局，所在省份为浙江，具体城市尚未命名。中国和浙江边界标红，浙江有省域示意点，始终注明当前所在区域；该点不代表实际校园经纬度。地理场景使用有轻微高低变化的网格和海陆光照，山脉起伏是艺术化示意，不是测量高程。长城、埃菲尔铁塔、自由女神像、金字塔、泰姬陵、悉尼歌剧院、富士山、莫斯科红场、大本钟和里约基督像共 10 处程序化地标，随范围显示，模型不按实际建筑比例制作。比例尺按当前地图中心和视角近似计算；左下使用用户指定的本地 SVG 图标与 **Open AI Map** 字样，不请求在线地图服务。

地理数据当前包含 **227 个国家/地区制图要素、4555 个一级区划**，中国有 34 个省级要素；国家/地区条目数不等于现实主权国家数。仅浙江另有 11 个地级市轮廓，其他省份和各国没有完整城市、道路与旅程数据。少数特殊区域没有一级区划，微型国家也可能只有一个区域，不伪造内部省份。源数据是制图概括，并非实时行政区登记。

按用户指定的中国方面口径呈现：中国使用完整轮廓，台湾为中国省级区域，香港、澳门与南海诸岛归入中国；南海断续线保留源数据的九段与台湾东侧一段，作为不可点选的辅助线。科索沃归入塞尔维亚，索马里兰归入索马里，北塞及缓冲区归入塞浦路斯，关塔那摩基地归入古巴，省级归属同步处理。中国轮廓与其他图源重叠处以中国轮廓优先。不确定的特殊区域按来源保留地区表达，继续核对中国方面资料；这些整理不构成官方标准地图审图或合规认证。

架空世界继续保留 **苏维埃社会主义共和国联盟**（`SUN`）：原十五个加盟共和国合并显示，其一级区划仍可浏览。目前只确认其版图存在，未设定历史、制度或相关剧情。国外放大继续浏览当地；返回校园只沿浙江家乡入口执行，不把普通地图浏览变成出行。

本地目的地显示预计耗时及路段事件。地图预告与移动结算使用同一确定性规则：基础 15 分钟、5 点精力，堵车或特殊事件可增加预告中的分钟数；同一状态下反复查看不会重新抽取事件。点事件标记只看详情，确认“前往”才移动、结算并写入日记。其他层的缩放、地区选择、访问或留学意向均不构成真实出行。

## 本地运行

开发需要 Node.js 24、npm 和 Python 3.10+。在项目根目录执行：

```bash
npm install

```

## 构建单张 PNG

准备有效封面 PNG，默认路径为 `assets/cover.png`，然后执行：

```bash
npm run build
python scripts/build_card.py --frontend dist/immersive-shell.js
python scripts/inspect_card.py dist/unread-city.png
```

也可以使用整合入口：

```bash
npm run card
```

`dist/immersive-shell.js` 是包含 Vue、Three.js、d3-geo、CSS、处理后的地理轮廓及内置 ST-iPhonie 的单文件 IIFE；完整内容写入 `data.extensions.tavern_helper.scripts`，PNG 不需要再托管这个前端文件。`scripts/build_embedded_phone.mjs` 从相邻的私有手机源码仓库 `D:\.study\ST-iPhonie` 读取白名单代码与资源，生成 `src/frontend/generated/embedded-phone.ts`；`npm run dev` 和 `npm run check` 的前置步骤会重新生成默认内嵌包，`npm run build` 随后将它并入同一 IIFE。维护构建需要该手机源码，导入成品 PNG 的设备不需要此目录。

默认构建不携带约 24 MB、304 项的原装音效包，手机中仍可手动导入音效。完整音效包属于高级构建选择，须检查最后产物中的资源；不能假设预先生成的带音效文件会在后续默认构建中保留。手机代码、样式和分词资源随卡携带；私人数据、设置、密钥与聊天存档不进入构建。3D 几何、静态降级图和地理资源也在本地打包。构建器使用固定脚本 ID 更新本项目脚本，保留其他扩展与其他脚本，不修改 `src/card.json`。附带的 P0/P1 使用说明仅追加到构建产物的 `creator_notes`。

自定义封面与输出路径：

```bash
python scripts/build_card.py --frontend dist/immersive-shell.js --image assets/your-art.png --output dist/my-card.png
```

不传 `--frontend` 时保留原有基础卡构建方式，只包含卡片数据和世界书；这类 PNG 不具有沉浸式界面。

## 玩家安装与进入

本项目供本人私用，目标包含手机上的 TauriTavern；记录版本便于维护，不设置额外的版本门槛。下述为接入方式，目标手机的实际兼容性仍需导入检查。

1. 在目标酒馆环境准备 [Tavern-Helper（酒馆助手）](https://github.com/N0VI028/JS-Slash-Runner)，确认它能加载角色脚本。ST-iPhonie 已随卡内嵌，无需再单独安装手机扩展。
2. 将构建好的 `unread-city.png` 作为角色卡导入 SillyTavern，打开该角色的新聊天。
3. 按酒馆助手提示授权、启用角色脚本。本卡脚本的数据字段设置为启用，首次执行仍受助手的授权机制控制；启用后会检查助手与当前单人聊天，满足条件时自动进入。
4. 退出后使用脚本按钮 **“进入未读之城”** 重新打开全屏界面；使用 **“恢复原生界面”** 或界面内退出入口回到原生聊天。
5. 使用模型叙事前，在 SillyTavern 选择 **Chat Completion（聊天补全）** 并连接模型；桥接检查的 `mainApi` 值为 `openai`，它表示酒馆的聊天补全接口类别，不要求模型供应商必须是 OpenAI。

点击常驻金色“手机”按钮，在悬浮窗中打开真实 ST-iPhonie；后台随 Shell 连接，窗口按需展示。已有兼容实例时优先复用，否则启用内置手机。加载失败会显示原因与重试入口；关闭手机窗回到场景，Shell、阅读位置和世界进度保留。人物页可直接打开对应手机会话，金色入口显示当前剧情空间的真实未读数。开场示例 NPC 与示例消息会同步进该聊天的剧情手机空间，示例内容仍不代表正式设定。

PNG 使用标准 V2 元数据承载脚本。普通 PNG 查看器和未安装酒馆助手的酒馆不会因此获得脚本执行能力；“单张 PNG”携带本项目界面和手机应用，但不安装酒馆、酒馆助手或配置模型服务。当前支持单人角色聊天；现有编解码器只维护 V2，重新嵌入时会移除旧 `chara` / `ccv3` 元数据。

## 运行与恢复机制

全屏 Shell 覆盖原生聊天，Tavern-Helper Bridge 负责识别当前聊天、读写状态、调用叙事生成和订阅切换事件。退出会清理当前 Shell 的挂载与会话监听，恢复原生滚动与焦点，不删除原生聊天 DOM。切换聊天后退出当前 Shell，并使当前异步请求失效；在目标聊天重新使用“进入未读之城”。界面的切换入口先退出，由用户在原生酒馆选择聊天。延迟返回的旧聊天回复不能提交到新聊天。

取消会立即使本次结果失效，并尝试按生成 ID 停止该请求，不停止其他脚本或原生聊天的生成。助手在极早取消时存在底层请求尚未登记的竞态，因此上游生成仍可能继续；本项目仍会丢弃迟到结果，不能把“取消”理解为必然已停止模型服务端工作。

当前世界权威状态使用聊天变量 `unread_city`，包括其中的 `story` 叙事记录和 `phone` 剧情收件，持久化依赖酒馆助手。时间、地点、体力、余额和日程通过确定性运行时更新；真实手机会话由插件维护，读回执只回填对应剧情事件的 `read` 状态。叙事以纯文本展示，模型结构化输出经校验后才入档，不执行代码、HTML 或任意状态补丁。模型生成结果不直接写入原生聊天楼层；`story` 与原生聊天记录仍分开，原生上下文与楼层双向同步未实现。

## 手机与剧情联动（2026-10-17 最新决定）

NPC 使用稳定 ID 对应真实手机联系人；显示名称不作为唯一身份。手机剧情空间的 ID 为 `SHA-256(JSON.stringify([角色头像文件名, chatId]))`，同卡不同聊天分开。仅当前剧情空间参与 Shell 未读显示，不导入、复制或覆盖旧手机历史。

“继续故事”的模型回复使用结构化 JSON：`{"story":"正文","phone_messages":[{"npcId":"lin","text":"消息"}]}`。固定协议由本轮临时 system 提示说明，状态和玩家行动保留在 user 输入中；其他世界书或预设的旧展示协议不适用于此轮，不修改用户的全局世界书。只接收当前存档已有 NPC 的文本消息，不从普通正文猜测收件。格式或 NPC 校验失败则整轮不提交；程序生成稳定事件 ID，先保存正文和收件，再交给手机投递。重开、重连和刷新可重试同步，同一事件不重复入手机。

已读状态从真实手机回传：只打开首页或联系人列表不清空未读，实际打开会话后更新前端数字角标和世界收件记录；收起手机后保留未读。生成等待期间收到的已读回执在回复提交时仍保留，避免旧状态把已读改回未读。聊天切换、退出后的迟到生成与旧回执不得写入新聊天。

当前联动范围为 **剧情收件 + 已读回传**，真实模型已完成一轮有消息、一轮无消息的本机验收。手机手动回复自动推动世界、手机与原生聊天楼层双向同步仍未实现。前一阶段接口及 PNG 验收见 `integration/extensions.json` 的 `validation.phoneStoryLinkCheck`，真实模型联调另见 `validation.llmConnectionCheck`；手机 TauriTavern 真机仍需导入检查。

正常退出后可以重新进入；可使用 Vue 外独立的“恢复酒馆”按钮退出，也可以使用酒馆助手的“恢复原生界面”脚本按钮。在 Shell 父页面按 Esc 时，先关闭悬浮窗，再将展开阅读缩回普通阅读，最后退出 Shell；焦点在手机 iframe 内时，沿用手机原有的 Esc 内部返回规则。实现还检查挂载节点、脚本 iframe 与当前聊天是否仍有效，异常时清理本项目界面。若目标环境的助手不能加载或执行任何脚本，刷新页面、禁用本卡脚本后可使用原生聊天。实机验收使用测试角色或新聊天，保留已有存档。

前一阶段手机托管实机已验证手机关闭回场景、重开保留 App、iframe 内 Esc 只退出 App、切地图释放手机，以及前往图书馆后的世界状态保存。手机打开时点击 Shell 的“切换聊天”入口可恢复原生界面，原生悬浮手机随后仍能打开。外部聊天切换事件与脚本卸载等异常路径有自动化覆盖，但不能据此声称已全部实机操作；本次界面重构后需重新部署复验。
